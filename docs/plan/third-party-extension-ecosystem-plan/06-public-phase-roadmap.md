# 06 — 公开阶段路线（登记，不实施）

> Phase F。本文是"先内部后公开"（README 决策 1）里**公开那一步**的前置项清单——现在只登记轮廓与触发条件，**不设计细节、不写码**。目的有二：① 内部阶段的所有设计不堵死这些路（各章已按此约束设计）；② 公开决策做出时，有一份现成的启动 checklist，不用从头盘点。
> ⚠️ 纪律：本清单里的任何一项，在公开决策做出前**不要提前做**——每一项都有真实运营成本（注册系统要防滥用、签名要管密钥、审核要有人值班），提前建 = 建一个没人用还得维护的半成品。

## 0. 触发条件

启动 Phase F 的前提（缺一不发公开邀请）：

- [ ] 内部阶段跑出 ≥ 若干个非本团队作者的真实扩展（数字由运营定），Phase B–E 的开发者旅程被外人完整走通过
- [ ] extension-api 面向 1.0 的收敛评估完成（§3）——公开后 breaking 的成本陡增一个量级
- [ ] 恶意扩展的响应值班与下架 SOP 有人认领（§2）——公开生态没有"没人管"这个选项
- [ ] 法务/开源策略对 LICENSE、商标（包名/scope）、用户协议的确认

## 1. 发布侧：从"运维签发"到"自助注册"

- **publisher 自助注册（拆半，2026-08-10 修订；2026-08-11 再修订）**：注册页 + 注册 API 已随内部阶段落地（见 [04 §2](./04-publishing-backend.md)，无登录态一次性表单 + IP 节流 + 保留名单）；2026-08-11 起注册改**审批制**（pending → 管理员批准后方能发布，配套最小审批页 `gallery/admin`）。公开阶段剩余：邮箱验证、命名防仿冒（与知名 publisher 编辑距离过近的名字进人工审核）、`publishers.json` 模型平移进真正的数据层（届时再评估 SQLite/托管 DB——静态 JSON 到那时才真正不够用）。
- **token 自服务**：网页端签发/轮换/吊销（替代 `token.mjs` 人肉通道与"注册页一次性显示"的不可再查语义，脚本降级为运维兜底）。
- **限流与滥用防护升级**：publish 频率限制、包体/版本数配额、register 的 IP 节流从内存级升级为持久/分布式——04 §2 刻意从简的项在此兑现。
- **管理台（2026-08-11 修订：范围缩减）**：仅审批的最小管理页已随内部阶段落地（04 §2）；公开阶段剩余**publisher 自视角**（我的扩展/下载量/版本管理）+ **运营视角完整版**（审核队列/强制下架/批量操作）。04 §8 对完整管理台的封印到这里解除。

## 2. 安全侧：签名、审核与响应 SOP

- **VSIX 签名硬化（2026-08-10 修订）**：服务端发布时签名（Ed25519 signVsix，versionEntry 写 sha256+signature）已随内部阶段落地（见 [04 §3](./04-publishing-backend.md)），编辑器 fail-closed 验签生效。公开阶段剩余是密钥运营管理：HSM/KMS 托管、轮换、吊销链。
- **上架审核**：至少"首个扩展人工过目 + 后续版本抽查"的轻量制；自动扫描（静态特征/已知恶意模式）作为辅助。
- **恶意上报与响应 SOP**：用户侧上报入口 → 值班响应时效承诺 → `control.json` 下架（客户端 quarantine 链路已就绪，缺的是流程与人）→ 事后通告。
- **软隔离的再评估**：公开生态下"接近编辑器本身的权限"的诚实边界是否仍可接受，届时重新评估 Node 权限模型硬隔离（同为 marketplace-plan Phase E 登记项）。**评估结论出来前，UI/文档的措辞红线不变**。

## 3. API 侧：1.0 冻结与 proposed API

- **1.0 冻结**：`COMPATIBILITY.md` 已定冻结条件（语言 provider 迁移完成、window/workspace 覆盖内置所需、契约测试全覆盖）。公开前完成一轮"淘汰候选"清理——0.x 是最后的低成本 breaking 窗口，公开后每个 breaking 都在伤害仓库外的真实代码。
- **proposed API 机制**（README 决策 8 的兑现点）：对标 VSCode `enabledApiProposals`——实验 API 需 manifest 显式声明 + 市场拒绝带 proposal 的包上架，只允许开发模式使用。1.0 后新 API 一律先走 proposal 熟化。0.x 阶段不建（当前整个面就是实验期，机制没有区分度）。
- **弃用运行时告警**：`COMPATIBILITY.md` 弃用机制里"首次调用 console.warn"落实为宿主基建。

## 4. 工程与运营侧

- **npm CI 自动发布**：tag 触发 + npm provenance（01 §3 "先手动"的后半句）；发布集合五包统一走。
- **token 存储升级**：`uex login` 的明文本地配置升级 OS keychain（03 §3.4 登记项）。
- **文档英文化与文档站**：`docs/extension-dev/<locale>/` 平移出静态站（对标 code.visualstudio.com/api）；API 参考 typedoc 化（05 §2 登记项，与 1.0 冻结同步）。
- **samples 独立仓库**：`samples/` 平移（05 §4 登记项），配 issue 模板与社区贡献流程。
- **生态运营**：扩展精选/排行、发布公告渠道、作者社区（论坛/群）、贡献者行为准则。
