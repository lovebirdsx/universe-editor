## 本次重点

Perforce 拉取排障补上了证据链：同步历史能回答「这么多次 p4 调用到底花在哪」（按命令类别拆开），由 δ 执行的那次拉取可以直接打开它自己的**运行日志**；不确定编辑器用的是哪一份 p4delta 时，一条命令给出**版本、来源与路径**。Git 侧调了一处按钮行为：工作树里不再显示 **发布分支**。

## Perforce 拉取

- **「花在哪」**：同步历史详情把 δ 那一半调用按命令类别拆开，次数多的在前，例如 `sync 740 · ignores 332 · fstat 3`。类别名就是 p4 的命令名，不翻译——要和 p4delta 日志、脚本对得上。这份拆分**是否完整单独判断**：不是一份通过验证的完整账，就注明是下界；引擎不报告分类、或这条记录写在分类上线之前时显示「未采集（该引擎不报告按命令的分类）」，**不是 0**。见[拉取历史记录](doc:perforce/sync-history)。
- **打开 p4delta 日志**：由 δ 执行的拉取，详情里会多一个 **打开 p4delta 日志** 按钮——δ 引擎自己一步步做了什么、每个阶段收了多少文件、最后是什么结论。日志以只读**快照**在新标签页打开；运行还没结束时打开的是「截至此刻」。日志留在**执行这次拉取的那台机器**上（远程开发时不在你本地），按运行独立保存、有大小与保留上限，被清掉时会明确提示。纯原生 p4 的拉取没有这个按钮。
- **两条排障命令**：**Perforce: 显示 p4delta 输出**（实时诊断频道——收集改动、清理文件、后台扫描这类不进历史记录的 δ 操作也在这里）与 **Perforce: 打开最近一次 p4delta 日志**（取时间上最近的一次，包括**此刻仍在跑**的那次）。
- **Perforce 输出频道不再复读**：一次运行结束后不再把 δ 的输出整段回放，Perforce 频道只留开始 / 结束摘要与运行编号；逐行诊断实时出现在 **P4delta** 频道，不再挤在同一个时间戳下。
- **导出 CSV 新增列**：调用分类（`p4Calls.p4deltaByCommand` 写成 `sync=740; ignores=332`、`p4Calls.p4deltaByCommandComplete`）与 δ 运行引用（`deltaRunId`）；没有这些项时同样留空，不写 0。

## 用的是哪一份 p4delta

- **Perforce: 显示 p4delta 信息**：弹出当前生效副本的**版本、来源与完整路径**——来源是优先级顺序里的那一级（`env` / `configured` / `managed` / `path` / `localAppData`），版本取自引擎自报，不是编辑器从目录名猜的。一个可用副本都没找到时，它会明说正在走原生 p4，并指向 **Perforce 输出**里的原因。见 [Perforce](doc:perforce/resolve-and-advanced)。

## 源代码管理（Git）

- **工作树里不再显示「发布分支」按钮**：链接工作树中的分支多是临时任务分支、不打算推送，所以提交按钮在那里不会变成 **发布分支**（回退为平时的灰色提交按钮）。主仓库的按钮行为不变；确实要在工作树里发布，运行命令面板里的 **Git: 发布分支** 命令。见[分支与合并](doc:git/branches-and-merge)。

## 图谱（Git / Perforce）

- **选中行失焦后改为浅色高亮**：图谱列表失去焦点（比如点去别的面板）时，选中行改用与资源管理器一致的浅色高亮、列文字转为次要色——不再看起来仍处于活动状态。Git 与 Perforce 图谱一起变化。见 [Git 图谱](doc:git/git-graph)。

## 升级注意事项

- **「花在哪」要求较新的 p4delta 引擎上报分类**：托管副本会照常后台升级，之后的新拉取才有分类；用环境变量或 `perforce.p4delta.path` 显式指定的自装副本**不会**自动升级，需要自己更新（**Perforce: 安装或更新 p4delta**）。历史记录不会补齐这项统计。
