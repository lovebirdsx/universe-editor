## 问题修复

- **Perforce：p4delta 装不上 / 升不了级的限流问题**。编辑器自行安装 p4delta 时，「最新版是哪个」此前问的是 GitHub API——它按出口 IP 每小时只放 60 次，共用一条出口的机器经常正好被拒（403 限流），表现为反复检查却始终装不上。现在改读 releases 页面的跳转地址，不再消耗 API 配额；日志里也会写清失败是「配额用完了」还是「被网络策略挡了」。
- **贡献命令首次点击偶发失效**。Perforce、Markdown 这类由扩展提供的命令，如果点下去的瞬间该扩展的 `activate()` 还在跑，这一击会抢先到达而落空，得再点一次。现在激活事件之间会互相等待（对齐 VSCode 1.74+），首次点击要么等到激活完成、要么直接把这个扩展拉起来。
- **点了不存在的命令，报错说得清楚了**。执行一个扩展并未注册的贡献命令（例如该扩展因本窗口不是它的工作区而提前退出），不再是一句含糊的失败，而是明确告诉你「该命令不存在」——与 VSCode 一致。
- **Perforce 命令按工作区收拢**。打开的文件夹不属于任何 Perforce 工作区时，命令面板里不再列出 `Perforce: …` 命令（此前会列出来、点了才报错）。这条门控覆盖全部 Perforce 命令，包括与工作区无关的机器级操作——想装 / 更新 p4delta，得先打开一个 Perforce 工作区窗口再运行 **Perforce: 安装或更新 p4delta**。详见 [Perforce](doc:perforce/overview)。

## 更新行为

- **重要更新会自己下载**。修紧急问题的版本会被标记为「重要更新」：`update.mode` 为**自动检查**（默认）或**启动时检查**时，编辑器发现它后会在后台自行下载，标题栏与状态栏用「重要更新」字样标出；你不用点「下载」，但要重启编辑器（或点提示里的「立即重启」）完成安装，正常退出也会顺带装上。把 `update.mode` 设成**手动**或**从不检查**时编辑器不自行检查更新，这条不适用。详见[常见问题](doc:reference/troubleshooting)。
- **修复并入同一篇说明**。一次修复不再另开一篇更新说明，而是补进它所属版本的介绍里；已经看过那个版本说明的用户不会因为一次修复被再次弹窗。想回看修复内容，在命令面板运行 **显示发行说明**（Show Release Notes）。

## 扩展开发

- 新增 VSCode 兼容的 `commands.executeCommand('setContext', key, value)`：扩展可以写上下文键，供 `when` 条件（菜单可见性、快捷键门控）判断。写入的键会保留到窗口重载为止，扩展若需要「关掉」它，得自己再写一次。
