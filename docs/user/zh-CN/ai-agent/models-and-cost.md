## 两套模型体系（重点）

编辑器里有两套模型，用途不同，别把它们搞混——改了一个不会影响另一个：

| | Agent 模型 | 平台 AI 模型 |
| --- | --- | --- |
| 作用对象 | 当前 Agent 会话 | 编辑器内置的 AI 功能 |
| 切换命令 | 选择 Agent 模型… | 选择 AI 模型 |
| 模型来源 | Agent 官方模型列表 + 当前认证供应商的网关模型 | 你在设置里配置的供应商模型 |
| 不可用时 | 提示"活跃 Agent 未提供模型选择器。" | 需先配供应商，否则列表为空 |

> 提示："选择 Agent 模型…"要求当前有活跃会话、且该 Agent 提供了模型选择器，否则会弹上表中的提示。

## 会话内切换模型

会话设定栏的 Model 下拉会列出当前会话可用的全部模型：Agent 自己的官方列表，**加上当前 Agent 认证所选供应商在对应协议下声明的模型**——也就是你在 AI 设置里配好的网关模型。网关模型可以直接在会话内切换，不必改认证或重开会话。

> 把会话切到上下文窗口更小的模型可能触发自动压缩，见[看上下文用量与自动压缩](#看上下文用量与自动压缩)。

Claude 会话在设定栏还有一个独立的**子 Agent** 触发器（人形图标），决定子 Agent 运行时用的模型，默认**跟随主模型**。它是独立弹窗、自带视口避让，所以主模型候选再多也不会把它挤出屏幕。这个选择经 Agent 进程的环境变量传递，所以改了要**下次会话才生效**；想立刻换，就点「立即重启」——编辑器会重启 Agent 进程并自动重连当前会话，**会话历史与当前配置都保留**。还没发过消息的空会话会被就地重建（Agent 侧没有可恢复的记录），你的输入草稿、标签页与配置同样保留。已被空闲回收而休眠的会话也支持「立即重启」：会先把它唤醒再重启。

## 一次配置，三处生效：接入第三方模型

接入第三方模型的关键不再是"到处填网关地址和密钥"，而是**在 AI 设置里配置一次供应商，多个入口直接选它**。一个供应商就是一条网关入口：连接信息（地址 + 密钥）+ 它能说哪些协议、每种协议下有哪些模型（`protocolMap`）。

配置步骤（在"打开 AI 与 Agent 设置" → AI 分组 → **供应商配置**）：

1. 点「添加供应商」，填 **id / 网关地址 / API 密钥 / 默认协议**。
2. 点「验证」确认能连上、能枚举到模型；再在 JSON 里把它的 `protocolMap` 写好（或留空数组让它从端点拉模型）。
3. 保存后，该供应商就出现在「Providers」列表里，可用于后续的模型选择。

**配好一个供应商，三处都能直接用**：编辑器的 AI 功能（对话、提交信息、内联补全、会话标题）、Claude Agent 的认证、Codex Agent 的认证，都改为**在下拉里选择这个供应商**，不再各录一遍地址和密钥——改密钥/地址也只需在这一个供应商上改一次。

| 目标 | 怎么接 |
| --- | --- |
| **Kimi K3**（Moonshot） | Moonshot 提供官方的 Anthropic 兼容端点：建一个 `anthropic-messages` 协议的供应商，把网关地址指向它、填上 key；Claude Agent 的认证选这个供应商即可。 |
| **GPT-5.6**（OpenAI） | 给 Claude 用时 OpenAI 不提供 Anthropic 兼容端点，需自行搭一层协议转换代理（如 LiteLLM proxy、claude-code-router），把 `anthropic-messages` 协议的供应商指向该代理。给 Codex 用时直接走官方 OpenAI（ChatGPT 登录或 API key），或用一个 OpenAI 兼容网关。 |

> 提示：Claude Agent 的认证需要**能说 Anthropic 协议**的供应商，Codex Agent 的认证需要**能说 OpenAI Responses 协议**的供应商。配供应商时选对协议，认证页的下拉才会把它列出来。

> 安全提示：**API 密钥是明文存在 AI 设置文件 `aiSettings.json` 里的**（这是刻意的设计，方便你把配置同步到别的机器）。编辑器会尽量把这个文件设成只有你自己可读（POSIX 下文件权限 0600）。因此**请不要把 `aiSettings.json` 提交进公共仓库、也不要把它放进不受控的同步目录**。

## 同类网关的多个入口：并存与分别计费

同一个网关可以建多个供应商条目——比如接了两家不同账号、或用了两个地址的同一个中转服务。要共享模型列表，可以让新条目用 `extends` 继承另一个条目的 `protocolMap`，只覆盖地址 / 密钥。它们的处理方式是：

- **并存使用**：多个供应商互不覆盖，随时在认证页/模型选择里切到另一个。
- **分别计费**：额度跟密钥（供应商）走，每个供应商各报各的用量，不会混在一起算。
- **手动切换，不做自动故障转移**：编辑器不会因为某个供应商连不上就自动帮你切到另一个。供应商卡片和认证页都有一个**连通性状态点**——打开设置页时会自动探测一次（结果缓存 5 分钟），之后编辑地址、密钥等连接字段也会自动重测——挑入口时看一眼绿点/灰点，连不上的别选。

## 配置网关价格与用量接口

每个供应商的费率只由它自己的 `pricingSource` 决定。`pricingSource` 有两种：

- `catalog`：查内置的官方价目表，`options.vendor` 指定厂商（`anthropic` / `openai` / `deepseek` / `moonshot`），不发网络请求。
- `http-json`：从网关端点拉价目表（one-api / new-api / LiteLLM / OpenRouter 这类中转常用）。

**没声明 `pricingSource` 就是「费率未知」**——绝不会跨供应商去套官方价。这是刻意行为：中转网关有折扣/加价/换币种，套官方价会记错账。如果你的网关暴露了价格表和账号用量接口，可以这样配：

```jsonc
{
  "providers": [
    {
      "id": "my-gateway",
      "baseUrl": "https://my-gateway.example.com/v1",
      "apiKey": "sk-...",
      "defaultProtocol": "openai-chat",
      "protocolMap": { "openai-chat": ["qwen3-coder"] },
      // 价格接口：拉网关的模型价目表
      "pricingSource": {
        "id": "http-json",
        "options": {
          "path": "/v1/pricing",          // 拼在 baseUrl 后面（缺省 /v1/pricing）
          "itemsPath": "data",            // 数组/对象所在字段，缺省 = 根
          "modelField": "id",             // 模型 id 所在字段，缺省 = "id"
          "fields": { "input": "input", "output": "output" },
          "unit": 1000000,                // 单价按多少 token 计价（缺省 = 每 1M）
          "currency": "CNY"               // 价目表币种
        }
      },
      // 用量接口：拉该账号的额度/余额（权威数字）
      "usageSource": {
        "id": "http-json",
        "options": {
          "path": "/api/user/self",       // 缺省 /api/user/self
          "itemsPath": "data",
          "fields": { "used": "used", "limit": "quota", "remaining": "remaining" },
          "unit": 500000,                 // 网关内部 1 美元 = 500000 信用点
          "kind": "quota"                 // quota | balance | subscription
        }
      }
    }
  ]
}
```

字段含义：`path` 是接口路径（拼到网关地址后面）；`itemsPath` 是放数据数组/对象的字段（缺省 = 整个响应）；`fields` 把网关返回的字段名映射成编辑器要的"输入价/输出价"（或"已用/上限/剩余"）；`unit` 做单位换算（价目表按每千 token 计价就写 `1000`，用量接口按网关信用点写除数）；`currency` 指定币种。抓取结果缓存在本地（费率 24 小时、用量 5 分钟刷新一次），拉取失败就静默用回旧值，绝不打断正常请求。

## 按功能分配模型

编辑器的多个 AI 功能可以各用各的模型（例如内联补全用更小更快的模型省钱）。在"打开 AI 与 Agent 设置"的 AI 分组 → 「功能模型」分类里，可为四类功能分别指定模型：

| 功能 | 界面名 | 说明 | 单独命令 |
| --- | --- | --- | --- |
| 对话 | 对话 | AGENTS 会话与对话补全使用的模型 | 由 Agent 模型控制 |
| 提交信息 | 提交信息 | 生成 Git 提交信息使用的模型 | 选择提交信息模型 |
| 内联补全 | 内联补全 | 编辑器幽灵文本补全使用的模型（可选更小更快的） | 选择内联补全模型 |
| 会话标题 | 会话标题 | 为 AGENTS 会话生成友好标题使用的模型 | 选择会话标题模型 |

## 看一次会话花了多少钱

- 输入框下方有一个 **¥ 人民币开销** 的小标签，悬浮时提示"会话费用 - 点击查看明细"。
- 点击它会弹出"会话费用明细"，按模型列出输入 / 输出 token 数、各模型开销和总计。
- 数据来自 Agent 上报的真实用量（含子任务开销）；无法精确统计时会标注为"预估会话费用"。
- 会话开销是**本地估算**：token 数 × 费率。费率**只看该供应商声明的 `pricingSource`**——查内置官方价目表（`catalog`）或网关价目表（`http-json`）；没声明就是"**费率未知**"（一个「—」+ 引导去填费率的入口），**不会拿一个相近型号的价格来猜，也不会套用别的供应商或官方价**。

> 会话开销（这一次会话烧了多少钱）与下一节的**账号额度**（你的账户还剩多少配额）是两回事，来源和性质都不同，谁也不会拿对方的数据来冒充自己。

## 看订阅额度还剩多少

用 Claude 或 Codex 的**官方订阅**（claude.ai 的 Pro / Max 登录、Codex 的 ChatGPT 登录）时，按的不是金额而是**额度窗口**：每 5 小时、每周各有一个用量上限，用满就要等它重置。输入框下方、会话计时右侧的小标签会显示这个用量：

小标签显示什么，取决于**当前会话所在主机上生效的凭据**——也就是那台机器上 Agent 自己的配置文件（Claude 的 `settings.json` / `.credentials.json`，Codex 的 `config.toml` / `auth.json`）实际在用哪一种：

| 当前会话所在主机上生效的凭据 | 小标签显示 |
| --- | --- |
| Claude 官方订阅 | 百分比（最紧的那个窗口还剩多少） |
| Codex 官方订阅（ChatGPT 登录） | 百分比，同上 |
| Claude 走内部 API 网关 | `¥` 月度用量（与以前一致） |
| Codex 走 API key / 网关 | 不显示 |
| 手写的、不对应任何供应商条目的凭据 | 不显示（编辑器不会硬猜它属于谁） |

> **本地与远端各算各的。** 额度和费用都归属于**会话所在的那台主机**：本地用 claude.ai 订阅、远端主机走内部网关时，本地会话显示订阅额度窗口，远端会话显示该网关的账号用量，两者互不干扰——即使这两个会话开在同一个窗口里。在 CLI 里重新登录、或直接手改 Agent 的配置文件，编辑器会自动跟上，不需要回设置页里重新选一次。

点击小标签会展开明细：每个额度窗口一条进度条，标出剩余比例与重置时间（"3 小时后重置"这类相对时间，超过一天则显示具体时刻）。展开时会顺带刷新一次数据。

- **走 API key / 网关时的账号额度**：如果你给供应商配了[用量接口](#配置网关价格与用量接口)（`usageSource`），供应商卡片和会话里会显示这个**上游权威数字**（额度 / 余额 / 订阅上限），额度跟哪个密钥（供应商）走就是哪个供应商的数。**配了用量接口但一时拉不到数字时，会显示"不可用"，绝不会拿本地估算值来冒充**。
- **Codex 的「重置限额」**：如果你的账户有可用的限额重置额度，明细里会出现「重置限额」按钮，点击并确认后会**消耗一张**额度立即解除当前限流。这个动作不可撤销，所以会先弹确认框；确认后按结果给出提示（已重置 / 当前没有被限流 / 没有可用额度 / 失败）。额度有保质期：数量旁会标注最早一张的过期时间（如「最早 3 天后过期」），过期即作废，别攒着不用。
- **数据来自 Agent 进程本身**，编辑器不会为了读用量而额外唤起 Agent。会话闲置一段时间、Agent 进程被回收后，小标签显示的是**最后一次读到的缓存值**，此时数字会变淡并倾斜，悬浮可看到"数据截止于 ⋯"的时间。点击它会立即尝试重新读取。
- 刷新节奏与"多久算过期"可在设置里调：`acp.subscriptionUsage.refreshIntervalMs`（默认 60 秒）、`acp.subscriptionUsage.staleAfterMs`（默认 10 分钟）。

> 这个小标签与上一节的 **¥ 会话费用**是两件事：会话费用算的是**这一次会话**烧了多少钱，订阅额度看的是**你的账户**在当前窗口里还剩多少配额。

## 看上下文用量与自动压缩

对话越长，占用的上下文窗口越多。快满时 Agent 会**自动压缩**（把较早的对话摘要成更短的内容）以腾出空间。编辑器在两处给出提示：

- **发送按钮的圆环**：外圈进度弧表示当前上下文占用比例；悬浮可看具体的 token 用量。
- **接近阈值预警**：占用达到 **80%** 时，输入框上方会出现一个「上下文 XX% · 接近自动压缩」的提示条，达到 **90%** 时转为红色。未达阈值时不显示。
- **压缩状态卡片**：真正开始压缩时，时间线里会出现一张系统卡片——压缩进行中显示「正在压缩上下文…」，并带一条进度条与「XX% · 用时」实时提示（进度为按耗时估算，用于直观反馈进展）；完成后变为「上下文已压缩」并显示总用时，失败则显示失败原因。

> 压缩由 Agent 自动完成，你无需手动干预；压缩后发送按钮圆环会立即刷新为压缩后的真实占用。

压缩只影响 Agent 的工作记忆，不会丢失你的对话记录：重新打开发生过压缩的会话时，压缩前的完整对话会照常回放，压缩发生的位置显示一张「上下文已压缩」卡片。

> 把长会话切换到**上下文窗口更小的模型**（例如从带 1M 上下文的型号切到标准 200k 型号）时，如果当前占用已超出目标模型的容量，编辑器会先弹确认框——继续切换会在下一条消息立即触发压缩；想保留完整上下文，请改选带更大窗口（如「1M context」）的型号。

## 看一次会话跑了多久

会话运行时间只累计 Agent **实际运行的净时长**，不包含挂起或等待你输入的时间。
