## 两个入口

配置 AI 供应商有两个入口，改的是同一份数据：

- **图形界面**：命令面板运行「打开 AI 与 Agent 设置」，打开可视化的 AI 设置编辑器。供应商的每个字段都能在这里改，改完立即生效，字段旁会闪一下「已保存」。推荐日常使用。
- **JSON 文件**：命令面板运行「打开 AI 设置（JSON）」，直接编辑配置文件 `aiSettings.json`。适合批量改动或从别处粘贴一整段配置。

两边是同一份文件：在编辑器外改了 `aiSettings.json`，设置页会自动跟着刷新（你正在输入的输入框不会被覆盖）。

按 `Ctrl+Shift+P` 打开[命令面板](../reference/glossary.md#命令面板)后，输入上面的命令名即可。

## 添加一个供应商

一个 AI 供应商就是**一条网关入口**：连接信息（地址 + 密钥）加上一份「它能说哪些协议、每种协议下有哪些模型」的声明。在 AI 设置编辑器里点「添加提供方」，第一个字段是**模板**：

| 模板 | 用途 |
| --- | --- |
| OpenAI (official) | 官方 OpenAI 端点，自动配好官方价目表 |
| Anthropic (official) | 官方 Anthropic 端点，自动配好官方价目表 |
| DeepSeek | 官方 DeepSeek 端点，自动配好官方价目表 |
| Ollama (local) | 本机 Ollama，无需密钥 |
| OpenAI-compatible gateway | 第三方 OpenAI 兼容网关，地址你填 |
| Custom (blank) | 全部自己填 |

选一个模板会预填 Base URL、默认协议、协议映射和价格来源——**预填不锁定**，你可以逐项改。`Provider id` 和 `API 密钥`模板永远不填，必须你自己给。

剩下的字段：

| 字段 | 说明 |
| --- | --- |
| Provider id | 全局唯一的短 id（不能含 `/`），也是它名下所有模型 id 的第一段 |
| Base URL | 服务地址，留空则用该协议的官方默认地址 |
| API 密钥 | 访问服务的密钥，可选（本地服务通常不需要）；右侧眼睛图标可切换明文/掩码 |
| 默认协议 | 编辑器侧未指定协议时用的协议 |

填好 id 和一个合法的 Base URL 后会自动尝试连接并列出可用模型的数量；也可以随时点「验证」手动触发。地址格式不完整时会提示，但**不阻止创建**——本地端点有时确实不带 scheme。

添加好的供应商会显示徽标：有没有配密钥、枚举到多少个模型、有没有配置问题，一目了然。卡片右上角的复制按钮可以整条复制一份（id 自动加 `-copy` 后缀），适合「同一个网关、换个密钥」的场景。

## 声明这个供应商提供哪些模型

供应商提供哪些模型，由它的**协议映射**（协议 → 模型列表）决定。在设置页展开供应商卡片，找到「协议与模型」一节，每个已声明的协议是一个块。

**每个协议有两种模式**，右上角的下拉框切换：

- **从端点发现**：每次启动都问端点要一次模型清单。适合模型经常变的网关；缺点是离线不可用，而且清单变了你不会察觉。
- **静态清单**：清单写死在配置里，完全不碰网络。适合要离线可用、或者想固定住可用模型的场景。

下面的按钮把两种模式串起来：

- **「固化 N 个模型为静态清单」**（发现模式下）：把当前拉到的模型一次性写成静态清单。这是从「每次启动都拉网络」切到「离线可用」最省事的一步。
- **「探测端点…」**：向端点要一次清单，弹窗里勾选你要的那些写进静态清单。清单很长时可以用顶部的过滤框筛，默认只勾前 50 个；超过 200 个会提示你考虑改回「从端点发现」。确认时只按你的勾选处理**这次探到的**模型：取消勾选的会被移掉，端点这次没报的（比如已下架、或超出条数上限）原样保留，已经改过名或收窄过能力的条目也不会被打回成普通名字。
- **「添加模型」**：直接手输一个模型名回车。端点连不上（离线、没密钥）时，这是建立静态清单的唯一办法。

协议本身也能增删：块右侧的垃圾桶图标删掉一个协议，底部的「添加协议」下拉添加尚未声明的协议。**删掉最后一个协议会先弹确认**——没有协议的供应商不提供任何模型。

**单条模型的高级编辑**：静态清单里每行右侧的铅笔图标可以展开，改三件事：

- **线上模型名**：端点实际认的名字，也是模型 id 的第三段。
- **知识库条目**：上下文窗口、厂商、能力这些元数据从哪儿读。当网关把一个知名模型改了名（比如把 `claude-sonnet-5` 挂成 `house-sonnet`），这里选 `claude-sonnet-5`，元数据就对了。
- **能力**：只能关、不能开。做协议翻译的网关只会丢失特性，不会凭空造出特性，所以知识库里没有的能力这里是灰的。

改完保存时会自动归一化：如果你只是填了个模型名、没改别的，配置文件里就还是一个普通字符串，不会平白多出一层对象。

模型 id 是三段 `供应商 id/协议/模型名`。比如 `acme-test/anthropic-messages/acme-chat-pro` 表示：`acme-test` 这个供应商、走 `anthropic-messages` 协议、端点上叫 `acme-chat-pro`。

顶层 `models` 是可选的**知识库**：存模型与网关无关的内在属性（显示名、家族、厂商、原生协议、上下文窗口、能力等）。静态清单里的字符串会按同名去这里查，查不到就当成「裸模型」直接使用，不报错。**费率不在这里**——见下一节。

其中上下文窗口的字段名是 `maxInputTokens`（输入 token 上限），例如 `"models": { "acme-chat-flash": { "maxInputTokens": 128000 } }`。这个值还会在开 Codex 会话时传给它——Codex 内置的模型表里没有网关模型，不填就只能按它自己的默认值管理上下文，压缩时机可能不准。

只有当 Codex 会话要跑的模型**既不在 Codex 自己的内置模型表里、这里也查不到**时，编辑器才会提示一次引导你来补（同一个模型不重复提示）。Codex 的官方模型（`gpt-5.6-sol` 这类）Codex 自己就知道窗口大小，不需要你填。

同级的 `modelSettings` 存单个模型的参数（键是三段模型 id，如 `"acme-test/anthropic-messages/acme-chat-pro": { "temperature": 0.3 }`）。设置页里模型行的齿轮图标就是编辑它。

## 模型知识库（模型配置）

AI 设置编辑器的「模型配置」分类把顶层 `models` 知识库做成了图形化编辑（以前只能手写 JSON）。它管的是模型**与网关无关的内在属性**——同一个模型无论走哪家网关都不变：

- 显示名称、模型系列、厂商、原生协议
- 最大输入 / 最大输出 token（上下文窗口大小）
- 能力（流式 / 视觉 / 提示缓存 / 工具调用）
- 推理强度档位
- 请求参数（JSON schema）

**价格不在这里。** 价格是 (通道, 模型) 的函数，走哪家供应商就在哪家的价格来源里配（见[价格与用量来源](#价格与用量来源)）。

面板分两个列表：**你的模型**（你自己添加的条目）和**内置模型**（随编辑器发布并持续更新的官方条目）。

**覆盖内置模型**：在内置条目上点「覆盖」，会为你建一条空记录——只改需要变的字段，**其余字段继续跟随内置定义**。以后内置目录更新（比如厂商调大了 token 上限），你没改过的字段会自动跟上。想把某个字段恢复成内置值，把输入框清空即可，字段会回到内置值并标注「内置：⋯」；想整体放弃覆盖，删除这条记录即可（会先确认「恢复为内置定义」）。

**重命名模型 key**：卡片上的重命名按钮会同步更新显式引用它的供应商条目；按线上模型名引用的供应商无法跟随，重命名前会点名提示——这些模型将失去元数据，但照常可用。

## 让多个入口共用一份配置（继承）

同一个网关有多个入口（比如公司网和家庭网两个地址、或者同一网关下两个不同额度的密钥）时，不必把配置抄两遍：在卡片的「继承自」下拉里选一个已有供应商即可。

- **协议映射整体替换**，不合并：子条目一旦自己声明了协议映射，父条目的就完全不作数。
- **其余字段逐项覆盖**：`baseUrl` / `apiKey` / `defaultProtocol` / `pricingSource` / `usageSource` 各管各的，子条目没写的就用父条目的。
- **id 永不继承。**

设置页会把继承状态标出来：继承来的字段在输入框下方标「继承自 xxx」，你自己填了值的字段标「覆盖 xxx」并给一个叉号，点一下就清掉覆盖、恢复继承。继承来的 API 密钥只显示「继承自 xxx」，**不会把父条目的密钥明文显示出来**。

自动连通性检测与「探测端点…」按继承后的实际连接信息去连——一个只写了 `extends` 的条目，用的是父条目的地址和密钥。

下拉里只会列出不会成环的候选（自己和自己的下游都不在里面）。即便如此，选中后仍会先用真实的解析逻辑跑一遍——继承层级太深之类的问题会当场拦下来并说明原因，不会写进文件。

## 价格与用量来源

一个供应商的费率**只由它自己声明的价格来源决定**。没声明就是「费率未知」——编辑器不会拿别家的官方价来套（中转网关有折扣、有加价、还可能换币种，套官方价等于记错账）。唯一的例外是继承：`extends` 的子条目没自己声明时，用的就是父条目那份（见上一节）。

「价格来源」和「账号用量来源」都是**可折叠区，默认折叠**——这两项配好之后基本不再改动。折叠状态下标题旁的摘要就是当前配置（例如 `HTTP JSON · /v1/pricing · CNY · 12 个模型`），点标题展开才是完整表单。折叠状态会记住，重启后保持。

在「价格来源」下拉里选：

- **无**：费率未知。模型行显示「费率未知」，会话开销显示「—」。若该条目 `extends` 了别人，这一项会写成「继承 xxx」——选它是清掉本地设置、回到继承，而不是真的变成「没有来源」。
- **内置目录**：用编辑器内置的官方价目表。选好之后下面会出现**厂商**下拉（anthropic / openai / deepseek / moonshot）。
  > 注意：目录按**线上模型名**查价。如果网关把模型改了名（上一节的 `house-sonnet`），查不到就是查不到——这种渠道应该自己声明价格来源。
- **HTTP JSON**：从网关自己的价目表接口拉。下面的表单里填路径（默认 `/v1/pricing`）、是否附带 API 密钥、币种；更细的字段映射（条目路径、模型 id 字段、输入/输出/缓存字段名、单位换算）收在「高级」折叠区里。

「账号用量来源」同理，只有「无」和「HTTP JSON」两种（默认路径 `/api/user/self`），另外多一个「用量类型」（额度 / 余额 / 订阅）。配好之后：

- **卡片头部会出现用量徽标**（例如 `¥0.09 / ¥3,000`，余额类显示剩余），鼠标悬停看完整明细。卡片折叠时徽标依然显示——这是「状态」，不需要展开才能看。
- 展开「账号用量来源」区可以看到同一组数字的明细行，以及「刷新用量」按钮。
- 拉不到权威数字时徽标显示「不可用」，**不会用本地估算值顶上**。

两个表单底部都有「编辑原始 JSON」——表单没覆盖到的选项（自定义请求头等）在这里改，JSON 不合法时会报错并且**不写盘**。

> **会话开销和账号费用是两回事，互不兜底。** 会话开销是本地按 token × 费率估算的；账号费用是上游给的权威数字。查不到就如实显示「—」或「不可用」，绝不用估算值冒充权威数字。详见[模型选择与花费](../ai-agent/models-and-cost.md)。

## 接入 OpenAI 兼容端点

很多本地或第三方服务（如 LM Studio、vLLM、DeepSeek 等）提供「OpenAI 兼容」的接口。接入方法：

1. 点「添加提供方」，模板选 `OpenAI-compatible gateway`（DeepSeek 直接选 `DeepSeek`）。
2. Base URL 填入该服务的兼容端点地址，填好 Provider id 后创建。
3. 展开卡片的「协议与模型」，`openai-chat` 默认是「从端点发现」；想固定清单就点「固化…」或「探测端点…」。
4. 如果该服务不需要认证，API 密钥留空即可（连接时会省略认证信息，不会报错）。

## 接入本地部署的 Ollama

如果你在本机跑了 Ollama：

1. 点「添加提供方」，模板选 `Ollama (local)`——Base URL 会自动填成 `http://localhost:11434`，协议是 `ollama`。
2. 填一个 Provider id，创建。
3. `ollama` 协议默认是「从端点发现」，会列出你本机已下载的模型。
4. 本地服务无需 API 密钥。

## 设置与清除 API 密钥

除了在添加供应商时填写，你随时可以单独管理密钥。

**在图形界面里**：进入某个供应商的详情，点密钥旁的铅笔图标就地输入并保存，或点叉号清除（会先确认）。密钥始终以掩码显示（未设置时显示「未设置」）。

**用命令面板**：

- 「设置 AI 提供方 API 密钥」：先选一个供应商，再输入密钥。
- 「清除 AI 提供方 API 密钥」：选一个供应商，确认后清除。

## 密钥安全：你需要知道的

API 密钥是敏感信息。编辑器的保管方式是一个**有意的设计取舍**，请记住这几点：

1. **明文保存在 `aiSettings.json` 里。** 为了让你能在多台机器之间同步同一份 AI 配置，密钥会直接写进 AI 设置文件的 `apiKey` 字段，不再使用操作系统的加密存储。
2. **权限尽量收紧。** 在类 Unix 系统上，编辑器会把该文件设为仅本人可读写（权限 0600）；Windows 上则依赖你用户目录本身的权限保护。
3. **界面上始终掩码显示。** 密钥只显示前 4 位和后 4 位；它不会被写进日志，也不会出现在 AI 调用记录（AI Debug）里。

> ⚠️ 正因如此，**`aiSettings.json` 里含有你的密钥**，请务必注意：
>
> - **不要**把它提交到公共版本库，也**不要**随工作区分享给别人。
> - 放进云同步目录（网盘、iCloud、OneDrive 等）时，请确认该目录可信。
> - 分享配置给别人之前，请先删掉各供应商的 `apiKey` 字段。

**请不要**把密钥写进其它任何设置文件——编辑器只认 `aiSettings.json` 里供应商的 `apiKey` 字段。

## 配置文件里有什么

如果你打开 AI 设置文件 `aiSettings.json`，会看到这些内容：

- `providers`：你添加的供应商（网关入口），含 id、Base URL、`apiKey`（密钥，明文）、`extends`、`protocolMap`、`pricingSource` / `usageSource`。**这些字段在设置页里全都能改**，直接编辑 JSON 只是另一条路。
- `models`：可选，模型知识库（覆盖内置条目）。
- `modelSettings`：单个模型的参数，键是三段模型 id。
- `activeModels`：当前为对话、内联补全等分别选中的模型 id。

例如：

```jsonc
{
  "providers": [
    {
      "id": "openai-official",
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "sk-这里换成你的密钥",
      "defaultProtocol": "openai-chat",
      // [] = 从端点发现；非空数组 = 静态清单，完全不碰网络
      "protocolMap": { "openai-chat": [], "openai-responses": [] },
      "pricingSource": { "id": "catalog", "options": { "vendor": "openai" } }
    },
    {
      "id": "acme-test",
      "baseUrl": "https://acme.example/v1",
      "apiKey": "sk-这里换成你的密钥",
      "defaultProtocol": "anthropic-messages",
      "protocolMap": {
        // 字符串 = 端点上就叫这个名字，元数据按同名查知识库
        // 对象 = 网关改了名：id 是线上名，ref 指向知识库条目
        "anthropic-messages": ["claude-sonnet-5", { "id": "house-fast", "ref": "claude-haiku-4-5" }]
      },
      "usageSource": { "id": "http-json", "options": { "kind": "quota" } }
    },
    {
      // 同一个网关的第二个入口：只换地址，其余全部继承
      "id": "acme-home",
      "extends": "acme-test",
      "baseUrl": "https://acme-home.example/v1"
    },
    {
      "id": "ollama",
      "baseUrl": "http://localhost:11434",
      "protocolMap": { "ollama": [] }
    }
  ],
  "activeModels": {
    "chat": "openai-official/openai-chat/gpt-5.4"
  }
}
```

> 上面 `apiKey` 用的是占位值；实际文件里会是你的真实密钥，所以这个文件请勿公开分享。

文件缺失或为空时，编辑器不会合成任何默认供应商，你需要在 AI 设置里自己添加。

## 检测到旧格式配置怎么办

如果你之前的 `aiSettings.json` 还是旧的两层格式（带 `providerTypes` 或 `providers[].type` 字段），编辑器会把它按空配置处理，AI 设置页顶部会显示一条 banner，提示你按上面的新格式手工重建（旧文件里的密钥可以复制出来）。**旧文件本身不会被改写。**
