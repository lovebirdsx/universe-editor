## 两个入口

配置 AI 供应商有两个入口，改的是同一份数据：

- **图形界面**：命令面板运行「打开 AI 与 Agent 设置」，打开可视化的 AI 设置编辑器，添加供应商、验证连接、管理模型参数都在这里。推荐日常使用。
- **JSON 文件**：命令面板运行「打开 AI 设置（JSON）」，直接编辑配置文件 `aiSettings.json`，适合高级用户（模型的协议映射、费率/用量来源等只在这里配）。

按 `Ctrl+Shift+P` 打开[命令面板](../reference/glossary.md#命令面板)后，输入上面的命令名即可。

## 添加一个供应商

一个 AI 供应商就是**一条网关入口**：连接信息（地址 + 密钥）加上一份「它能说哪些协议、每种协议下有哪些模型」的声明。在 AI 设置编辑器里点「添加提供方」，填写：

| 字段 | 说明 |
| --- | --- |
| Provider id | 全局唯一的短 id（不能含 `/`），也是它名下所有模型 id 的第一段 |
| 标签 | 可选，一个好认的名字 |
| Base URL | 服务地址，留空则用该协议的官方默认地址 |
| API 密钥 | 访问服务的密钥，可选（本地服务通常不需要） |
| 默认协议 | 编辑器侧未指定协议时用的协议 |

点「验证」会尝试连接并列出可用模型的数量；连接失败会显示错误原因。

添加好的供应商会显示徽标：有没有配密钥、枚举到多少个模型、有没有配置问题，一目了然。

## 声明这个供应商提供哪些模型

供应商提供哪些模型，由它的 `protocolMap`（协议 → 模型列表）决定。这个字段在 `aiSettings.json` 里编辑：

- **空数组 `[]`**：从该供应商的端点拉取模型列表，完全不写死在配置里。
- **非空数组**：直接就是这些模型，完全不碰网络。
- 数组元素可以是字符串（就是模型名），也可以是对象 `{ id, ref, capabilities, … }`：`id` 是端点上线的真实模型名，`ref` 指向内置知识库（或你自己在顶层 `models` 里定义的条目），其余字段覆盖知识库；能力只能关不能开（翻译链路有损，中转网关只会少能力、不会凭空多能力）。

模型 id 是三段 `供应商 id/协议/模型名`。比如 `kuro-gbl/anthropic-messages/deepseek-v4-pro` 表示：`kuro-gbl` 这个供应商、走 `anthropic-messages` 协议、端点上叫 `deepseek-v4-pro`。

顶层 `models` 是可选的**知识库**：存模型与网关无关的内在属性（显示名、家族、厂商、原生协议、上下文窗口、能力等）。`protocolMap` 里的字符串会按同名去这里查，查不到就当成「裸模型」直接使用，不报错。**费率不在这里**——费率是（渠道，模型）的组合属性，由供应商自己的 `pricingSource` 决定（见[模型选择与花费](../ai-agent/models-and-cost.md)）。

同级的 `modelSettings` 存单个模型的参数（键是三段模型 id，如 `"kuro-gbl/anthropic-messages/deepseek-v4-pro": { "temperature": 0.3 }`）。

同一个网关的多个入口（比如公司网和家庭网两个地址）用 `extends` 继承另一个供应商条目：`protocolMap` 整体替换、其余字段（`baseUrl` / `apiKey` / `label` 等）逐个覆盖。配置写错（环引用、指向不存在的 id、继承层级太深）会在这条供应商上标出问题并跳过它，不会悄悄丢弃。

## 接入 OpenAI 兼容端点

很多本地或第三方服务（如 LM Studio、vLLM、DeepSeek 等）提供「OpenAI 兼容」的接口。接入方法：

1. 点「添加提供方」，默认协议选 `openai-chat`。
2. Base URL 填入该服务的兼容端点地址。
3. 在 `aiSettings.json` 里把它的 `protocolMap` 的 `openai-chat` 写成 `[]`（从端点拉模型）或具体模型列表。
4. 如果该服务不需要认证，API 密钥留空即可（连接时会省略认证信息，不会报错）。

## 接入本地部署的 Ollama

如果你在本机跑了 Ollama：

1. 点「添加提供方」，默认协议选 `ollama`。
2. Base URL 通常无需填写，默认就是本机的 Ollama 地址 `http://localhost:11434`。
3. 在 `aiSettings.json` 里把它的 `protocolMap.ollama` 写成 `[]`（从本机 Ollama 拉取已下载的模型）。
4. 本地服务无需 API 密钥。

## 设置与清除 API 密钥

除了在添加供应商时填写，你随时可以单独管理密钥。

**在图形界面里**：进入某个供应商的详情，用「编辑 API 密钥」和「清除 API 密钥」按钮操作。密钥会以掩码显示（未设置时显示「未设置」）。

**用命令面板**：

- 「设置 AI 提供方 API 密钥」：先选一个供应商，再输入密钥。
- 「清除 AI 提供方 API 密钥」：选一个供应商，确认后清除。

## 密钥安全：你需要知道的

API 密钥是敏感信息。编辑器的保管方式是一个**有意的设计取舍**，请记住这几点：

1. **明文保存在 `aiSettings.json` 里。** 为了让你能在多台机器之间同步同一份 AI 配置，密钥会直接写进 AI 设置文件的 `apiKey` 字段，不再使用操作系统的加密存储。
2. **权限尽量收紧。** 在类 Unix 系统上，编辑器会把该文件设为仅本人可读写（权限 0600）；Windows 上则依赖你用户目录本身的权限保护。
3. **界面上始终掩码显示。** 密钥只显示前 4 位和后 4 位；它不会被写进日志，也不会出现在 AI 调用记录（AI Debug）里。

> ⚠️ 正因如此，**`aiSettings.json` 里含有你的密钥**，请务必注意：
>
> - **不要**把它提交到公共版本库，也**不要**随工作区分享给别人。
> - 放进云同步目录（网盘、iCloud、OneDrive 等）时，请确认该目录可信。
> - 分享配置给别人之前，请先删掉各供应商的 `apiKey` 字段。

**请不要**把密钥写进其它任何设置文件——编辑器只认 `aiSettings.json` 里供应商的 `apiKey` 字段。

## 配置文件里有什么

如果你打开 AI 设置文件 `aiSettings.json`，会看到这些内容：

- `providers`：你添加的供应商（网关入口），含 id、标签、Base URL、`apiKey`（密钥，明文）、`protocolMap`、`pricingSource` / `usageSource` 等。
- `models`：可选，模型知识库（覆盖内置条目）。
- `modelSettings`：单个模型的参数，键是三段模型 id。
- `activeModels`：当前为对话、内联补全等分别选中的模型 id。
- `agentSettings`：各 Agent 的编辑器侧设置（认证选择、模型覆盖）。

例如：

```jsonc
{
  "providers": [
    {
      "id": "openai-official",
      "baseUrl": "https://api.openai.com/v1",
      "apiKey": "sk-这里换成你的密钥",
      "defaultProtocol": "openai-chat",
      "protocolMap": { "openai-chat": [], "openai-responses": [] }
    },
    {
      "id": "ollama",
      "baseUrl": "http://localhost:11434",
      "protocolMap": { "ollama": [] }
    }
  ],
  "activeModels": {
    "chat": "openai-official/openai-chat/gpt-5.4"
  }
}
```

> 上面 `apiKey` 用的是占位值；实际文件里会是你的真实密钥，所以这个文件请勿公开分享。

文件缺失或为空时，编辑器不会合成任何默认供应商，你需要在 AI 设置里自己添加。

## 检测到旧格式配置怎么办

如果你之前的 `aiSettings.json` 还是旧的两层格式（带 `providerTypes` 或 `providers[].type` 字段），编辑器会把它按空配置处理，AI 设置页顶部会显示一条 banner，提示你按上面的新格式手工重建（旧文件里的密钥可以复制出来）。**旧文件本身不会被改写。**
