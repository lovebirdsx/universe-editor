## 什么是扩展

扩展是给编辑器增加额外能力的小模块。你不需要手动下载或启用它们——下面这六个都随编辑器一起装好，开箱即用。

## 六个内置扩展

### AI Assist

帮你借助 AI 更快地干活。目前最直接的一项是：在[源代码管理](../reference/glossary.md#源代码管理scm)面板的提交输入框旁提供一个图标按钮，点一下就能让 AI 根据你的改动自动写好一条提交说明。

<!-- 截图：SCM 输入框旁的 AI 生成提交信息图标 -->

### Claude Helper

帮你更顺手地编辑 Claude Code 的配置文件。当你打开 `.claude` 目录下的配置文件时，它会提供自动补全和检查，帮你避免写错字段。

### Git

帮你在编辑器里完成版本管理：提交、暂存、切换分支、推送、查看历史等等，一共提供五十多条 Git 相关命令。它是[源代码管理](../reference/glossary.md#源代码管理scm)面板背后的能力来源。详细用法见 [Git 概览](../git/overview.md)。

### Markdown Language Features

帮你更高效地编辑 Markdown 文档：在长文里快速跳到某个标题、在标题之间跳转、找出指向不存在位置的失效链接等。详细用法见 [Markdown 编辑](../editing/markdown.md)。

### Numbered Bookmarks

帮你在文件里放下 0 到 9 共十个编号书签，然后一键跳回。编辑时书签会跟着内容自动移动，行号旁还会显示书签图标，方便你在长文件里来回穿梭。详细用法见 [数字书签](../editing/bookmarks.md)。

### TypeScript Language Features

帮你更顺畅地阅读和编辑脚本文件（`.ts`、`.js` 等）：跳到定义处、查找引用、悬停查看说明、输入时补全、重命名，以及标出可能的错误。

## 为什么有些能力要打开对应文件才出现

为了不拖慢启动，扩展只在真正用得上的时候才「醒来」。所以你可能注意到某些能力要打开特定类型的文件后才出现：

| 扩展 | 什么时候开始工作 |
| --- | --- |
| Git | 编辑器启动完成后自动就绪 |
| Numbered Bookmarks | 编辑器启动完成后自动就绪 |
| TypeScript Language Features | 打开 `.ts`、`.js`、`.tsx`、`.jsx` 文件时 |
| Markdown Language Features | 打开 `.md` 文件时 |
| AI Assist | 首次使用「生成提交信息」时 |
| Claude Helper | 打开 Claude Code 配置文件时自动生效 |

> 提示：这就是为什么在纯文本文件里看不到脚本文件的跳转、补全——它们是脚本编辑专属的能力，打开对应文件后自然会出现。

## 安装第三方扩展

除了内置扩展，你还可以安装第三方扩展来扩充编辑器的能力。有两条途径：从**扩展市场**在线搜索并一键安装，或者从本地的 `.vsix` 安装包安装（`.vsix` 是与 VSCode 兼容的扩展打包格式）。

### 从扩展市场安装

1. 按 `Ctrl+Shift+X`，或点击活动栏（最左侧的图标竖栏）里的**扩展**图标（拼图形状），或运行命令 **扩展: 显示已安装扩展**（英文 *Extensions: Show Installed Extensions*），打开扩展视图。聚焦到扩展视图时，光标会自动落到顶部搜索框，可直接开始输入。
2. 视图分成「已安装」和「市场扩展」（英文 *Market Extensions*）两栏。「已安装」栏默认只列出你自己安装的扩展——内置扩展不占用列表，在搜索框输入 `@builtin` 即可列出它们（可再叠加关键词过滤，如 `@builtin monokai`），此时栏目标题变为「内置」（英文 *Built-in*）。搜索框留空时，「市场扩展」栏默认列出市场上最热门（按安装量）的可安装扩展；在搜索框里输入关键词后，该栏改为列出匹配的结果（本地查询如 `@builtin` 不触发市场搜索）。
3. 在某一项上点「安装」即可下载并安装；点击条目本身会打开详情页，可以查看说明文档（README）与它贡献的命令、配置、快捷键。

<!-- 截图：扩展视图的市场扩展栏与安装按钮 -->

> 发布版默认已接入官方扩展市场，打开扩展视图即可搜索安装。你也可以用启动参数 `--gallery-url` 或环境变量 `UNIVERSE_GALLERY_URL` 指向自建市场，或把地址置空以关闭市场（此时市场搜索为空，请改用下面的本地 `.vsix` 安装）。
>
> 注意：从市场安装的扩展包会经过**签名校验**——扩展包必须由市场方签名，未签名或校验失败的包会被拒绝安装。因此自建市场必须用配套的发布脚本（`pnpm gallery:publish`，见开发文档）发布扩展，指向未做签名适配的第三方市场（如 open-vsx）将无法安装。

### ESLint（市场扩展示例）

**ESLint** 是官方发布在市场里的第一方扩展（在扩展视图搜索 `ESLint` 即可安装）。它帮你在脚本文件（`.js`、`.ts`、`.jsx`、`.tsx` 等）里发现并修复代码风格与潜在问题。它使用你**工作区自己安装的 ESLint**（`node_modules` 里的那份），所以检查结果与你在命令行里跑 `eslint` 完全一致；如果工作区没装 ESLint，它会安静地不工作。装上后它能做四件事：

- **标出问题**：输入或保存时在有问题的代码下画波浪线，鼠标悬停可看规则说明，问题上的规则名可点击直接打开该规则的官方文档。
- **单条快速修复**：把光标放到问题处，点灯泡（或按 `Ctrl+.`）选择「Fix this … problem」修复这一条，或应用 ESLint 给出的建议改法。
- **一键修复全部**：运行命令 **ESLint: 修复所有可自动修复的问题**（英文 *ESLint: Fix all auto-fixable Problems*），把当前文件里所有能自动修的问题一次修好。
- **加禁用注释**：在灯泡菜单里选「Disable … for this line」，在问题行上方插入一行 `// eslint-disable-next-line` 注释来忽略该规则。

它还可以（默认关闭，按需在设置里开启）作为**格式化程序**运行，或在**保存文件时自动修复全部**。相关设置见下表：

| 设置项 | 作用 | 默认 |
| --- | --- | --- |
| `eslint.enable` | 是否启用 ESLint | `true` |
| `eslint.run` | `onType`（输入时检查）或 `onSave`（保存时检查） | `onType` |
| `eslint.validate` | 需要检查的语言 | JS/TS 四种 |
| `eslint.format.enable` | 允许「格式化文档」用 ESLint 修复 | `false` |
| `eslint.codeActionsOnSave.enable` | 保存时自动修复全部 | `false` |
| `eslint.options` | 直接传给 ESLint 的额外选项 | `{}` |

### 从本地 VSIX 安装

有两种方式：

- **命令安装**：打开[命令面板](../reference/glossary.md#命令面板)（`Ctrl+Shift+P`），运行 **扩展: 从 VSIX 安装…**（英文 *Extensions: Install from VSIX…*），在文件选择框里选中一个 `.vsix` 文件，点「安装」。
- **拖放安装**：直接把一个或多个 `.vsix` 文件从系统文件管理器拖到扩展视图里松手，即可安装。若拖入的文件里有任何不是 `.vsix` 的，会提示错误且不安装任何文件。拖入一个已安装扩展的更高版本 `.vsix` 会将其更新到新版本。

安装完成后扩展立即生效——它贡献的命令会出现在命令面板里，随用随激活。

### 更新、禁用与卸载

- **检查更新**：运行 **扩展: 检查扩展更新**（*Extensions: Check for Extension Updates*）。编辑器会对照市场检查所有来自市场的扩展，有新版本时自动更新并提示更新了几个。
- **禁用与启用**：不想卸载、只想临时停用某个扩展时，可以禁用它。禁用后该扩展不再加载、不再贡献命令与界面。有两种作用范围：
  - **全局**：对所有窗口生效。在扩展视图里把鼠标移到条目上，点右侧的齿轮按钮（或右键点条目）打开操作菜单，选「禁用 / 启用」，或运行 **扩展: 禁用扩展**（*Extensions: Disable Extension*）/ **扩展: 启用扩展**（*Extensions: Enable Extension*）。
  - **仅当前工作区**：只对当前打开的文件夹生效，换一个工作区就不受影响。需先打开一个文件夹，然后在条目的操作菜单（齿轮按钮或右键）里选「禁用（工作区）/ 启用（工作区）」，或运行 **扩展: 禁用扩展（工作区）**（*Extensions: Disable Extension (Workspace)*）/ **扩展: 启用扩展（工作区）**（*Extensions: Enable Extension (Workspace)*）。工作区设置优先于全局设置。
  - 内置扩展（Git、TypeScript 等）同样可以禁用；禁用后对应能力（如源代码管理、脚本语言智能）会随之关闭。内置扩展默认不显示在「已安装」栏——先在搜索框输入 `@builtin` 列出它们，条目标有「内置」标记，之后即可用操作菜单或上述命令禁用（命令面板里的 **扩展: 禁用扩展** 随时可选中内置扩展，不受列表显示影响）。
- **卸载**：运行 **扩展: 卸载扩展…**（*Extensions: Uninstall Extension…*）从列表里选择要移除的扩展，或在扩展视图里从条目的操作菜单（齿轮按钮或右键）选「卸载」。内置扩展不能卸载，只能禁用。
- **版本不兼容自动禁用**：要求更高编辑器版本的扩展（`engines.universe` 不满足当前版本）会被自动禁用并提示原因，其贡献的命令与界面不会出现；这类条目在扩展视图里标为「已禁用」，点开可看到具体原因（需要哪个版本的编辑器、当前是多少），且不提供启用/禁用按钮。从市场安装或更新扩展时，编辑器会自动挑与你当前版本兼容的最新版本；一个兼容版本都没有时，安装按钮会禁用或提示无法安装。

### 扩展可以提供的自定义预览

有些扩展会为特定文件类型注册**自定义编辑器**——你双击该类型的文件时，打开的不是普通文本视图，而是扩展提供的图形界面。市场里的 **PDF Viewer** 扩展就是一例：装上后，双击 `.pdf` 文件会直接在标签页里渲染 PDF（基于 Mozilla pdf.js），可翻页、缩放、跳转。

另一例是 **Excel Viewer & Diff** 扩展：装上后双击 `.xlsx` / `.xls` / `.csv` 会在标签页里渲染表格；它还支持**表格对比**——在资源管理器里对一个表格文件点右键选「选择以进行比较」，再对另一个选「与所选项进行比较」（或直接选中两个表格文件后选「比较所选文件」），即可并排查看两份表格的单元格级差异（新增/删除/修改高亮，可按 sheet 切换、只看差异行）。这套比较菜单是资源管理器内置的通用入口——文本文件走普通文本 diff，表格文件则自动交给该扩展渲染。若同时装了 Git 或 Perforce 扩展，对表格文件执行「Open Changes」也会用这种表格 diff 对比当前版本与仓库中的版本。

这类界面运行在一个受限的内嵌页面（iframe）里：它只能加载扩展自己目录下、以及扩展显式声明的少数几个位置的资源，并受内容安全策略（CSP）约束。但要注意——**这不是等同于浏览器网页的强沙箱**，承载它的扩展进程本身仍拥有接近编辑器的权限（见下方安全边界）。

### 关于安全边界

> ⚠️ **安全提示**：第三方扩展会以**接近编辑器本身的权限**运行——它们能访问你的文件和网络。编辑器**不会**把扩展关进沙箱，**安装即意味着相当程度的信任**。
>
> 为此编辑器做了三层保护，但它们只是提醒与兜底、不能替你判断：
>
> - **发布者信任提示**：首次安装某个发布者的扩展时会弹出确认，问你是否信任该发布者；确认后同一发布者的后续扩展不再重复询问。
> - **市场签名验证**：从市场下载的扩展包必须经过市场方签名验证，未签名或被篡改的包会被拒绝安装。这保证你装到的包就是市场发布的那一份。
> - **恶意扩展拦截**：市场会标记已知的恶意扩展，编辑器拒绝安装它们；若某个已装扩展事后被标记为恶意，会在下次启动时自动禁用并通知你。
>
> 本地 `.vsix` 安装不经市场签名验证——那是你自己显式选择的文件，请确保来源可信。
>
> 请只安装你信任来源的扩展。

## 开发自己的扩展

如果你在自己写扩展，不必每次改动都打包成 `.vsix` 再安装。编辑器提供了一套「扩展开发宿主」模式，与 VSCode 的 Extension Development Host 对齐：

- **从源码目录直接加载**：启动时加 `--extension-development-path=<扩展目录>`（目录里要有 `package.json` 和构建产物），该扩展就直接被加载，无需打包安装。参数可重复传多个目录；也可以用环境变量 `UNIVERSE_EXTENSION_DEV_PATH`（多个目录用系统路径分隔符拼接：Windows 是 `;`，macOS/Linux 是 `:`）。开发中的扩展优先级最高——与已安装或内置的同 id 扩展冲突时，永远以开发目录里的版本为准，且不受禁用状态影响。
- **独立的开发实例**：带上该参数启动的是一个独立的「扩展开发宿主」进程——它不参与单实例复用（不会只是聚焦到你已经打开的编辑器），并且默认使用独立的用户数据目录（`Universe Editor - ExtDev`）。**代价**：开发宿主里看不到主实例的主题、设置和已装扩展——两边互不影响正是隔离的目的。确需共享时可显式传 `--user-data-dir=<主实例目录>`，但两个实例并发写同一份设置文件有互相覆盖的风险，后果自负。开发宿主的窗口标题带 `[扩展开发宿主]` 标识，状态栏也会显示加载了几个开发中的扩展。
- **断点调试**：加 `--inspect-extensions=<端口>` 启动后，扩展宿主进程会在 `127.0.0.1:<端口>` 上开放 Node.js 调试协议，用 VSCode 的 attach 配置连上去即可在扩展的 TypeScript 源码里打断点（需构建时生成 sourcemap）。`--inspect-brk-extensions=<端口>` 则会在执行任何扩展代码前就停住，用于调试 `activate` 函数本身。扩展宿主重启（崩溃、手动重启或自动重启）后调试连接会断开，需要重新 attach。
- **保存即生效的自动重启**：开发宿主默认监听开发中扩展 `main` 入口产物所在目录的变更，重新构建后自动重启扩展宿主加载新代码（防抖约半秒），全程不用重启编辑器，也不用手动操作。该行为由设置 `extensions.autoRestartOnChange` 控制（默认开启，仅在扩展开发窗口生效）；首次自动重启时会弹一次性通知说明它会断开已 attach 的调试器。产物分散在多目录等监听覆盖不到的罕见形态、或调试 `activate` 本身想让重启时机可控时，可关掉该设置，在命令面板手动运行 **重启扩展宿主**（*Developer: Restart Extension Host*）——这个命令对所有用户都有用，某个扩展行为异常时也可以用它自救。
- **开发中的扩展在扩展视图里**带「开发中」徽标，且不提供卸载/禁用按钮（它不在已安装清单里，这些操作对它没有意义）。

一个典型的开发循环：

```bash
# 终端 1：扩展目录里 watch 构建（如 esbuild --watch）
# 终端 2：拉起开发宿主
universe-editor --extension-development-path=D:/dev/my-ext --inspect-extensions=9229
# 在 VSCode 里 F5 attach 到 127.0.0.1:9229 打断点
# 改代码 → 保存 → watch 重编 → 宿主自动重启加载新代码 → 重新 attach 继续调试
```
