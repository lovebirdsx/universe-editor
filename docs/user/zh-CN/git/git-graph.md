# 提交历史图（Git 图谱）

Git 图谱是一个专门用来**可视化浏览提交历史和分支**的编辑器。想看清"项目是怎么一步步走到今天的"、或者直接在历史上对某个提交动手，这里是最佳入口。

## 打开 Git 图谱

三种方式：

- 命令面板运行 **View Git Graph**（查看 Git 图谱）；
- 点源代码管理侧栏标题栏最左边的图谱图标；
- 或点击底部状态栏左侧的当前分支名称。

> 命令面板里这条命令显示的是英文 **"View Git Graph"**（分类 "Git Graph"），搜索时请用英文。

打开后是一个编辑器标签页，标题为 **"Git 图谱"**。

还有两个"带着目标提交来"的入口：从[时间线](./timeline.md#在图谱中查看提交)的行内按钮 / 右键菜单，或 Blame 悬停卡片里的 **"Open in Graph"** 链接——图谱会直接**选中并滚动定位到该次提交**，老提交未加载时自动向前翻页查找（最多补 20 页）。如果你已经在用"提交变更"视图，它还会自动跟随切换为这次提交的改动（静默更新，不会弹出侧栏或抢焦点）。

> 想直接看某次提交**改动的全部文件**（而不是它在历史里的位置），在图谱里单击该提交即可，或用时间线的 [Open Commit](./timeline.md#打开提交的全部改动open-commit)，或点击[状态栏 Blame 项](./blame-and-history.md#状态栏上的-blame)。

## 图谱里能看到什么

- **每行一个[提交](../reference/glossary.md#提交--commit)**，左侧是连线图（画出分支怎么分叉、怎么合并），右侧有作者、提交、日期、描述等列。
- 最顶部有一行 **"未提交的更改"**，代表你当前还没存档的改动。
- **单击某个提交**，源代码管理侧栏的"提交变更"视图会列出它改了哪些文件，并按状态着色（已添加 / 已修改 / 已删除 / 已重命名等）。点击文件行会打开该文件这次改动的差异；**Ctrl+单击再选一个提交**，则对比这两次提交之间的全部改动。点击 **"未提交的更改"** 行会跳转到源代码管理视图。视图标题栏还提供"在图谱中显示"（定位当前提交）、全部折叠 / 全部展开，以及"…"菜单里的树形 / 列表布局切换（选择会被记住）。"提交变更"视图的键盘操作与源代码管理视图一致：方向键移动，**空格**预览差异（焦点留在文件列表上，可继续上下翻看其它文件），**回车**打开差异并把焦点交给编辑器；命令面板里的 **"Focus on Commit Changes View"** 可随时把焦点移入该视图。

顶部还有一些视图设置（进阶，扫一眼即可）：提交顺序（作者日期 / 日期 / 拓扑）、"仅跟随第一父提交"、以及"加载更多提交"。

## 键盘导航

打开图谱时焦点就在提交列表上，无需先点击，整个图谱都可以纯键盘操作。没有历史记录可恢复时，会自动选中首个提交（跳过"未提交的更改"行），并像单击一样在"提交变更"视图显示它的改动；上次聚焦的提交会被记住，下次打开（包括重启应用后）仍保持选中并滚动定位到它：

- **↑ / ↓**：上移 / 下移选中提交，"提交变更"视图会像单击一样跟随切换。
- **Home / End**：跳到第一行 / 最后一个已加载的行（不会自动触发"加载更多提交"）。
- **PageUp / PageDown**：按当前可视行数翻页移动选中。
- **Enter**：把焦点移入"提交变更"视图的文件列表，接着用键盘翻看这次提交改了哪些文件（**空格**预览差异、**回车**打开差异）。
- **Ctrl+Enter**：对当前选中提交弹出与右键相同的操作菜单，锚点在选中行位置。如果这一行上有多个可操作目标（提交本身、分支 / 标签 / 远程 / 工作树标记），会先弹出快速选择框让你选哪一个；只有一个目标时直接弹出菜单。
- 弹出的菜单同样支持键盘：**↑ / ↓** 移动高亮（自动跳过分隔线），**Enter** 执行，**Esc** 关闭。

## 搜索提交

图谱编辑器处于激活状态时，按 `Ctrl+F` 聚焦搜索框（占位文字"搜索提交…"），输入关键词快速定位某次提交。

> 命令面板里这条对应 **Focus Search**（聚焦搜索），且只在 Git 图谱编辑器激活时才生效。

想按提交信息、哈希或作者**跳转**到某次提交，也可以在图谱激活时按 `Ctrl+R`（**Go to Symbol in Editor…**，转到编辑器中的符号）：弹出的列表按图谱顺序列出所有已加载提交，右侧带"短哈希 · 作者 · 日期"，上下键浏览只滚动预览，回车选中该提交并像单击一样在"提交变更"视图展示它的改动。

## 刷新图谱

图谱会自动跟随仓库变化刷新；需要手动拉一遍最新历史时，在图谱激活时按 `Ctrl+Shift+R`，或运行命令 **Refresh**（刷新，分类 "Git Graph"），与工具栏的 ↺ 按钮等效。

> 命令面板里这条同样显示英文 **"Refresh"**，且只在 Git 图谱编辑器激活时才生效。

## 显示或隐藏远程分支

想在图上看到[远程](../reference/glossary.md#源代码管理scm)分支，运行 **Toggle Remote Branches**（切换远程分支显示）来开关它们。图谱内也有对应的"显示远程分支""隐藏远程分支"入口。

> 命令面板里这条同样显示英文 **"Toggle Remote Branches"**，用英文搜索。

## 同步工作树

当仓库有多个工作树时，右键图谱中的工作树标记，可以选择 **将工作树同步到 {分支}…**。选择要同步的工作树后，编辑器会将它们重置到目标分支；有未提交更改的工作树会被跳过，未合入目标分支的提交也会保留。多个工作树会并行同步，执行期间右下角会显示进度通知，完成后弹出结果汇总。

需要丢弃干净工作树中尚未合入目标分支的提交时，选择 **强制将工作树同步到 {分支}…**。这仍会跳过有未提交更改的工作树，但会覆盖其已提交且未合入目标分支的内容；执行前请确认这些提交不再需要。

## 右键即操作

Git 图谱最强的地方，是可以直接在历史上对某个提交或分支**右键动手**。常用项包括：

- **检出此提交…**：把工作目录切到这个提交的状态。
- **在此处创建分支…** / **在此处创建标签…**：从这个提交开一条分支、或打一个标签。
- **合并到当前分支…**：把这个提交所在分支合进你当前的分支。
- **将当前分支变基到此提交…**、**将当前分支重置到此提交…**：进阶的历史整理操作。
- **拣选…**（cherry-pick）、**还原…**（revert）：单独把某个提交的改动挑过来、或撤销某次提交。
- **拣选到分支…**（Cherry-pick to branch）：把这个提交拣选到你**指定的另一条分支**上，而不是当前分支。会弹出分支选择框，选定后编辑器自动切到目标分支拣选、成功后再切回你原来的分支；若拣选遇到冲突，会停在目标分支等你处理。如果目标分支正被**另一个工作树**检出（Git 不允许两处同时检出同一分支），操作会直接在那个工作树的目录里完成——完成后会弹出"已在工作树 … 上完成"，告诉你改动落在了哪里；那个工作树若有未提交的更改，会拒绝执行而不是留下半套状态。
- **复制提交哈希** / **复制提交信息**：拷贝这次提交的编号或完整提交信息（含正文所有行）。鼠标悬停在提交信息上也会以悬浮提示显示完整内容。
- **发送到 Agent Chat**（Send to Agent Chat）：把这次提交的哈希和提交信息发到 AI 会话的输入框，方便让 agent 结合这次提交回答问题。没有活动会话时会自动新建一个。

对**远程分支**右键，可以 **作为本地分支检出…**：输入本地分支名后从远程跟踪分支新建并切换。如果本地已存在同名分支，编辑器会提供 **重置到远程分支** 选项——选择后还需在警告框中再次确认，确认后本地分支会被重置到远程分支的最新提交（未推送到远程的本地提交将丢失）。若该分支正被另一个工作树检出，重置会在那个工作树里就地完成，并弹出"已在工作树 … 上完成"；那个工作树有未提交更改时会拒绝执行。

> 术语提示：这里的 **检出** 和源代码管理侧栏里的 **签出** 是同一个动作（切换到某个提交/分支），只是界面用词不同。

> **危险操作要看清确认框**：重置（reset --hard）、强制推送这类操作会改写历史、可能丢失内容，编辑器会弹确认框。看清楚提示再点确认，别手快。

## 图谱不可用时

如果当前项目文件夹不是 Git 仓库，图谱会提示 **"Git 图谱不可用 - 此文件夹是 git 仓库吗？"**。让项目先成为仓库的办法，见 [版本控制是什么，为什么需要它](./overview.md#让你的项目变成仓库)。
