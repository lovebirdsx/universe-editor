## 面板长什么样

Perforce 面板按 **changelist** 把你签出的文件分组：

- **需要合并** 组置顶（有内容时才显示）：拉取或取出搁置后等待[解决冲突](./resolve-and-advanced.md#冲突解决resolve)的文件。
- **默认 changelist** 紧随其后，输入框里的文字就是它提交时的描述。
- 每个**编号 changelist** 一组，组名带上它的描述。
- 若某个 changelist 有搁置内容，它以子组的形式**嵌套在该 changelist 组下方**（与 p4v 一致）。

每个文件行右侧的字母标记它的动作：`edit` / `add` / `delete` / `S`（shelved）等。

> **长操作有进度提示**：submit、shelve、还原、删除 changelist 等可能较慢的 p4 操作执行期间，状态栏的 Perforce 条目会显示进度文案（如 `…branch_xyz: Syncing…`），旋转图标固定在文案最右，完成后自动恢复常态，让你清楚知道后台正在跑什么。扫描工作区（reconcile）这类操作还会显示 `已扫描目录数 / 总数` 计数，进度明细（已扫描 / 待扫描目录数、当前目录、已发现差异文件数、已耗时）悬停状态栏即可查看，详见[拉取版本与状态感知](./sync-and-status.md#状态栏)。

## 拉取

日常循环从「把别人提交的最新版本拿下来」开始（对应 P4V 的 Get Latest Revision）：

- Explorer 右键 **拉取最新版本**（一级菜单，目录也可用），或命令面板搜 "Perforce: 拉取最新版本"；点状态栏「可更新」计数则先弹出「要同步到哪个变更列表」（最新版本仍是第一项），选定后再拉整个作用域。
- 需要指定版本 / 强制覆盖 / 先看影响面，用右键 **Perforce ▸** 子菜单里的 **拉取版本…** 与 **预览将要拉取的内容**。
- 拉取范围跟随[聚焦目录](../search-navigation/focus-folders.md)（没开聚焦时 = 打开的文件夹），不是整个 depot。

完整说明（QuickPick 各档、错误引导、落后感知灰字与状态栏）见[拉取版本与状态感知](./sync-and-status.md)。

## 收集改动（reconcile）

和 Git 直接读磁盘不同，Perforce 面板默认只显示**已签出**的文件。如果你在编辑器外（或关闭自动签出时）改了、建了、删了文件，它们不会自动出现——但**资源管理器会提示你**：

未签出、但磁盘内容偏离 depot 的文件，会在资源管理器文件名旁显示 **RC** 徽标并变色，对标 Git 的未跟踪 / 已修改列表。它**只检查当前显示在屏幕上的那些行**（滚动到哪就查到哪），所以不会像全量扫描那样在大型 depot 上变慢。发现过未收集改动的文件，其各级父文件夹也会跟着染色（文件夹不带 RC 字母徽章）——不过没展开的子树查不到，文件夹的颜色是"已发现改动"的下界，可能随展开而变化。作用范围跟随[聚焦目录](../search-navigation/focus-folders.md)：开了聚焦时，范围外的文件即使改过也不标记。收集之后，标记会自动跟着变。不想要这个提示就关掉 `perforce.reconcileHint.enabled`（默认开），此后资源管理器不再触发任何 reconcile 扫描。

看到 RC 徽标后，可以：

1. **查看差异**：右键该文件选 **打开更改**，或打开文件后用 `Shift+Alt+Y`，看它与 have 版本的差异。
2. **收集进来**：在资源管理器右键 **收集改动**（一级菜单，目录也可用），集成跑真正的 `p4 reconcile`，把这些文件签出到对应的 changelist——文件随即离开「未收集」状态，出现在下方的 changelist 组里，就能提交了。拉取时若因本地有未收集改动而被跳过，提示条里也有「收集改动」按钮（见[拉取版本与状态感知](./sync-and-status.md)）。
3. **丢弃不想要的改动**：在资源管理器右键 **Perforce ▸ 还原**（会先确认），把该文件恢复到 have 版本——磁盘上改过的内容被丢弃、新增的文件被删除、被删的文件被找回。文件尚未签出时，效果等同以前的「丢弃未收集的改动」（`p4 clean`）；若选中包含已签出、在 changelist 里的文件，确认框会列出哪些文件将离开 changelist，避免误操作。**支持多选**：用 `Ctrl` 选中多个文件再右键，会作用于**整个选区中的文件**，确认框显示涉及的文件数量。
4. **直接归组**：从资源管理器把未签出文件拖到某个 changelist 的**组头**，即把它收集并直接归入该 changelist（底层 `p4 reconcile -c`），一步到位。

> 提示：[聚焦目录](../search-navigation/focus-folders.md)生效时，reconcile 的扫描范围会收窄到聚焦目录——超大 depot 上这是扫描的主要耗时来源（[拉取](./sync-and-status.md)的作用域同样跟随聚焦）。扫描进行中，悬停状态栏可看进度明细（已扫描 / 待扫描目录数、当前目录等）。但已签出文件列表（`p4 opened`）、整个 changelist 的还原与搁置仍是全 client 范围，不会因为开了聚焦就变成部分操作。

## 签出、新增、删除

Perforce 里改文件前要先"签出"。三种改动方式：

- **签出（edit）**：把已在仓库里的文件标记为可改。
- **新增（add）**：把新文件纳入版本控制。
- **删除（delete）**：把文件标记为删除（会有确认提示）。

有三处入口：

- **命令面板**（`Ctrl+Shift+P`）搜索 "Perforce: 签出 / 新增 / 删除"。
- **资源管理器右键**：常用操作在一级菜单——**拉取最新版本**、**收集改动**；其余（签出 / 新增 / 删除 / 还原、拉取版本…、预览将要拉取的内容、复制 Depot 路径、图谱与 Blame）收在 **Perforce ▸** 二级子菜单里。**打开更改** 也是一级菜单项，但归在通用的「比较」分组（与「选择以进行比较 / 与已选文件比较」同组），Git 文件同样有这一项。对**目录**右键可选 **收集改动**、**还原**（递归整个子目录）与 **拉取最新版本**。签出 / 新增 / 删除 / 还原 / 收集**支持多选**：用 `Ctrl` 选中多个文件再右键，操作会作用于**整个选区**（收集对目录按 `<dir>/...` 递归，其余命令只作用于选区中的文件），破坏性操作的确认框显示涉及的数量；拉取版本… / 预览将要拉取的内容 / 复制 Depot 路径仍作用于右键的那一项。
- **面板文件行 / 组**上用对应动作。

> 这些右键 / 标题栏入口只在文件归属某个 Perforce 工作区时出现——打开非 Perforce 仓库时不会显示 Perforce 菜单项。

## 自动签出

不想每次手动签出，可开启 `perforce.autoEdit`（默认关）。开启后，当你**编辑一个属于当前工作区、尚未签出的文件**时，集成会自动对它跑 `p4 edit`。这与许多团队的 Perforce 使用习惯一致。

> 自动签出只在你真正修改文件内容时触发，不会因为只是打开文件就签出。

## 对比与打开改动

- 在面板里**单击**文件行：打开本地版本与仓库 **have 版本**的差异对比。
- **打开当前文件的改动**：对活动编辑器里的文件直接开差异视图——快捷键 `Shift+Alt+Y`，或点编辑器标题栏的对比图标，或命令面板搜索 "打开更改"。

编辑器左侧的**改动色条（dirty-diff）**同样对 Perforce 文件生效：改动的行会显示色条，点色条弹出行内小 diff（have 版本 ↔ 当前内容），`Esc` 关闭。同一批改动行还会同步画到右侧总览标尺和小地图上，长文件里滚动时一眼就能看出改了哪几处；想只留其中一处显示，用设置 `scm.diffDecorations`（见 [改动色条的显示位置](../git/blame-and-history.md#自定义显示)）。详见 [Git 的改动色条说明](../git/session-changes.md)，Perforce 行为一致。

## 时间线（文件历史）

资源管理器侧栏的 **时间线（Timeline）** 视图对 Perforce 文件同样生效（来自 `p4 filelog` 的单文件修订历史，与 Git 的时间线并排工作）：

- 打开一个 Perforce 文件后，时间线视图列出它的全部修订：每行显示提交描述、相对时间与 changelist 号。
- **单击某一行**：打开该修订与**上一修订**的差异对比（新增的文件左侧为空、删除的修订右侧为空）。
- 文件有未提交改动时（已签出，或在磁盘上改过但还没签出），**第一页顶部会出现「待定更改」行**：单击打开工作区内容与 **have 版本** 的对比，右侧跟随你的实时编辑。可用 `perforce.timeline.showPending`（默认开）关掉这一行。
- 右键历史行可复制 changelist 编号；底部 **加载更多** 翻更早的历史。
- **打开某个 changelist 的全部改动（Open Commit）**：悬停历史行点行尾第一个按钮（差异图标），或右键选 **"Open Commit"（打开提交）**——打开源代码管理侧栏的"提交变更"视图：顶部是提交标题、作者与时间（悬停标题会以悬浮提示显示完整描述，含所有行），下面按文件列出该 changelist 改动的所有文件，并自动把焦点定位到当前文件那一行；点击任一文件行打开该文件与上一修订的差异（空格 = 预览差异且焦点留在列表，回车 = 打开并聚焦编辑器）。「待定更改」行没有这个入口。视图标题栏还提供"在图谱中显示"、全部折叠 / 全部展开，以及"…"菜单里的树形 / 列表布局切换（选择会被记住）。
- **在图谱中定位某个 changelist**：悬停历史行点行尾跳转按钮，或右键选 **"Open in Perforce Graph"（在 Perforce Graph 中显示）**——打开 [Perforce Graph](./perforce-graph.md)并选中、滚动定位到该 changelist（未加载时图谱自动向前翻页，最多补 20 页）。「待定更改」行没有这个入口。

> 想纵览**整个仓库**的提交历史（而不是单个文件），用 [Perforce Graph](./perforce-graph.md)。想只看**某个文件或文件夹**的历史（图谱式、可搜索、能联动"提交变更"视图），用 [Perforce Graph 的"只看一个文件或文件夹的历史"](./perforce-graph.md#只看一个文件或文件夹的历史)。

## 还原

**还原（revert）**把文件恢复到 have 版本（会有确认提示）。同一入口同时覆盖已签出文件和尚未签出的工作区偏离：

- **尚未签出**（资源管理器上有 RC 徽标）：效果等同丢弃工作区改动（`p4 clean`），不进 changelist。
- **已在 changelist 中**：退出签出并丢弃本地改动；确认框会列出哪些文件将离开 changelist。
- **单个文件**：在文件行或资源管理器右键用还原动作。
- **目录**：资源管理器对文件夹右键还原，递归处理该子目录（已签出的会列出将离开 changelist 的文件；未签出的工作区偏离一并丢弃）。
- **整组还原**：在默认 / 编号 changelist 组标题上用 **还原 Changelist 中的所有文件**，一次丢弃该组全部签出改动（会有确认提示）。
- **还原未改动文件（revert unchanged）**：只还原那些被签出但内容其实没变的文件，清理噪音很实用（安全，不会丢真实改动，无需确认）。

## 提交

1. 在默认 changelist 的输入框里填提交描述。
2. 点输入框旁的 **提交（submit）** 按钮，或命令面板搜 "Perforce: 提交默认 changelist"。
3. 也可以直接**提交某个编号 changelist**（在该组上用提交动作）。

> **默认动作随 Swarm 而变**：当 [Swarm 审核](./swarm-code-review.md)已开启且配置了服务器地址时，输入框旁按钮的**默认动作会变为「发起新的 Swarm 审核…」**——契合"改动先审核、再提交"的团队流程；点按钮旁的下拉箭头仍可切回直接提交。未启用或未配置 Swarm 时，默认动作保持为提交。

> 提交会直达中央 depot，**不可撤销**（不像 Git 有本地 amend / undo）。因此每次提交都会先弹确认框。提交成功后面板自动刷新。

## 刷新

Perforce 状态在服务器上，服务器本身没有文件监视器。集成在每次操作后自动刷新；你也可以：

- 用面板标题栏的**刷新**按钮手动刷新。刷新期间按钮会变为转圈加载态并暂时禁用，当前刷新完成后才恢复可点，避免重复触发。
- 开启**轮询**：把 `perforce.refreshInterval` 设为秒数（最小 10 秒，`0` 或留空为关闭），集成会定时刷新。详见[冲突解决与进阶设置](./resolve-and-advanced.md)。
