## 三种拉取方式

Perforce 的「拿版本」对应 `p4 sync`。编辑器提供三个命令，覆盖 P4V 里最常用的三条路径：

| 命令 | 什么时候用 | 入口 |
|---|---|---|
| **拉取最新版本** | 最常用：把最新（`#head`）拿下来，无确认、直接执行 | Explorer 右键（一级菜单）、命令面板 |
| **拉取版本…** | 需要指定版本：按 changelist / 日期 / 修订号，每种都可选**强制覆盖**（八档） | Explorer 右键 **Perforce ▸** 子菜单、命令面板 |
| **预览将要拉取的内容** | 拉之前先看会动哪些文件；只读，绝不改动任何东西 | Explorer 右键 **Perforce ▸** 子菜单、命令面板 |

## 拉取最新版本

入口：

- Explorer 右键一级菜单的 **拉取最新版本**（文件与目录都可用；对目录右键 = 递归拉取整个子目录）；
- 状态栏的修订指示器（如 `#68 / ↓#69`）——点击它只拉取**当前这个文件**；
- 命令面板搜 "Perforce: 拉取最新版本"。

上面三个入口都无需确认、直接执行。

Explorer 里支持**多选**：用 `Ctrl` / `Shift` 选中多个文件、目录再右键，拉取会对**整个选区**生效——每个目录展开为递归的 `<dir>/...`。选区里的路径跨越多个 Perforce 工作区时，会报错并中止这次拉取（一次 p4 sync 只能跑在一个 client 上）。

图谱的[合并历史标签页](./perforce-graph.md#一次查看多个文件文件夹的合并历史)里，行右键的 **获取最新修订** 同样作用于该标签页的**全部所选路径**，与上面的 Explorer 多选拉取是同一套执行流程。

完成后弹结果：**已更新 N 个文件**；有文件正被签出、p4 不会覆盖它们时，附「· M 个已跳过（正在签出中）」；有文件拉完需要合并时，附「· K 个需要合并」并提供 **解决冲突** 按钮，直接进入[冲突解决](./resolve-and-advanced.md#冲突解决resolve)流程。全部已是最新时提示 **已是最新版本**。

### 有文件被跳过：本地改了但没签出

如果文件在本地被改过却没签出，Perforce **不会**用服务器版本覆盖它——你的改动优先。此时拉取会跳过这些文件并提示 **N 个文件未更新——它们有尚未收集的本地修改**，附三个按钮：

- **收集改动**：把这些本地改动收集（签出）进 changelist。收集之后再拉一次，Perforce 就会把服务器的新版本与你的改动排进[合并](./resolve-and-advanced.md#冲突解决resolve)，两边都不丢。这是推荐路径。
- **查看差异**：先看清本地到底改了什么再决定（多个文件时先让你选一个）。
- **强制拉取**：弹出一个多选列表，列出所有被跳过的文件（默认全选，逐个取消勾选想保留的；文件名**黄色**=有未收集的本地修改），确认后用服务器版本覆盖**勾选的**文件。**勾选文件的本地改动会永久丢失、不可撤销**，列表标题会再提醒你这一点；只在确定这些本地改动是废弃的时候用。若服务器在目标版本**删除了**某个文件而本地仍有未收集的改动（p4 报 `can't delete modified file`），这类文件**不会**出现在强制拉取列表里——因为它那行带的是你本地已有的修订号，强行按它拉取只会把该文件按旧版本拉回来；用**收集改动**或**查看差异**处理它们。若被跳过的文件**全部**属于这一类，提示条干脆不再给出**强制拉取**按钮（列表会是空的）。

> 注意跳过与失败的区别：被跳过的文件不影响同一次拉取里的其它文件，它们照常更新——提示条会把两件事一起报（如「1 个文件未更新…… · 已更新 9 个文件」），不会因为有跳过就瞒下已经拿到的。

### 有文件被跳过：本地已存在未被跟踪的同名文件

另一种跳过是**本地已有一个 Perforce 没跟踪的同名文件**占了目标路径——典型来源是引擎安装残留、共享存储落下的二进制资产（`*.uasset` 的 `_BuiltData`、编辑器 `*.pdb`、解压出来的 `*.wav`）。它不是你的「改动」，只是磁盘上恰好有个同名文件挡在那里，而工作区配置不允许覆盖（`noclobber`）。此时提示 **N 个文件未更新——本地已存在未被跟踪的同名文件，已被跳过**，只附一个按钮：

- **强制拉取**：弹出一个多选列表，列出所有被跳过的占位文件（默认全选，逐个取消勾选想保留的；文件名**紫色**=未被跟踪的同名文件），确认后用服务器版本覆盖**勾选的**文件。**它会永久覆盖勾选的本地文件、不可撤销**，列表标题会再提醒你这一点。

> 与上一节的区别：上一节的文件是你的**改动**（值得先收集或看差异）；这一节的文件**不在 Perforce 视野里**，没有「改动」可收集、也没有内容可对比，所以不给「收集改动」「查看差异」——那不是对症的补救（收集会把引擎残留物误塞进 changelist）。如果你其实想保留那个本地文件，先手动把它挪走或改名，再重新拉取。

## 拉取指定版本

入口在 Explorer 右键 **Perforce ▸ 拉取版本…** 或命令面板 "Perforce: 拉取版本…"，弹出**八档**选择（对齐 P4V 的 Get Revision）：前四项是普通拉取，后四项以 **强制拉取：** 开头、整行**红色**显示，会覆盖本地文件（列表上方的提示语就写着「红色项为强制拉取，会覆盖本地文件」）。

Explorer 多选同样适用：先选中多个文件 / 目录再右键，选定版本后会对**整个选区**生效（跨工作区时的报错规则与[拉取最新版本](#拉取最新版本)相同）。

| 选项 | 含义 | 后续 |
|---|---|---|
| 最新版本 | 与「拉取最新版本」相同（`#head`） | 直接执行 |
| 指定 changelist 时的版本… | 拉取到某个 changelist 为止的状态（`@12345`） | 输入 changelist 编号 |
| 指定日期时的版本… | 拉取到某一天的状态（`@2026/08/01`） | 输入日期 `yyyy/mm/dd`，可带时间 |
| 指定修订号… | 拉取某个具体修订（`#4`） | 输入修订号 |
| **强制拉取：最新版本** | `#head -f`：覆盖本地文件，即使 Perforce 认为它们已是最新 | 二次确认 |
| **强制拉取：指定 changelist 时的版本…** | `@12345 -f`：同上，但目标版本是某个 changelist | 输入 changelist 编号，然后二次确认 |
| **强制拉取：指定日期时的版本…** | `@2026/08/01 -f` | 输入日期，然后二次确认 |
| **强制拉取：指定修订号…** | `#4 -f`：把文件强制拉到某个具体修订（可以比本机还旧） | 输入修订号，然后二次确认 |

输入框支持直接带前缀 `@` / `#`（如 `@12345`、`#4`），不会重复加前缀。

> **强制拉取会先确认**：确认框正文会点明**目标版本**（如 `@4521`、`#4`）与**这次要覆盖的范围**（单文件/多选时是那些文件的路径；无选区时是你当前的[拉取作用域](#拉取的作用域)，即工作区范围），并提示其中**未收集的改动（包括未被跟踪的同名文件）将丢失、不可撤销**。框里显示的就是**实际会执行**的目标版本——即使你在输入框里手打了 `#` 前缀把档位"改写"成了别的形态，以框里为准。

> **确认框有时有两个按钮**：当这次强制拉取由 p4delta 执行时，除了「强制拉取」，确认框还会给出「**强制拉取 + 删除未跟踪文件**」。第二个按钮在覆盖之外，**还会从磁盘删除**这次范围内 Perforce 从未跟踪、且**没有被 `.p4ignore` 覆盖**的本地文件——p4ignore 命中的、被范围排除的、以及范围外的文件都保持不动（p4ignore 保护的通常是构建产物，删掉它们正是这个功能要避免的）。文件被删后**不可恢复**，只在确定范围内那些本地文件都可以丢弃时使用；只用「强制拉取」按钮则不会删除任何未跟踪文件。p4delta 不可用、或这次的版本形态不支持删除档时，第二个按钮根本不出现。

## 预览将要拉取的内容

在 Explorer 右键 **Perforce ▸ 预览将要拉取的内容**。这是一次只读的预演（`p4 sync -n`）：不写任何文件、不改服务器。结果弹出一个列表，显示将要拉取的每个文件（文件名 + 动作 + 修订号，详情行给出 depot 路径）；选一个即可直接打开该文件。已经是最新时会提示 **已是最新版本**。

本地改了但没签出、拉取时会被跳过的文件也会列在这里，动作标为 **not updated**；若服务器在目标版本**删除了**某个文件而本地仍有未收集的改动，动作标为 **not deleted**——它们确实落后（或确实该被删掉），预览不会把它们藏起来。

适合在**拉取最新版本**或**强制拉取**之前先看一眼影响面。

> 预览是**那一刻**的清单。紧随其后的拉取按**执行时**的[范围文件](./resolve-and-advanced.md#关于工作区范围)重新解析它的范围，所以若这中间文件改了，实际会传的是新范围下的东西——此时编辑器会提示 **工作区范围在预览之后发生了变化——本次按当前配置执行**，让你知道刚才那份清单已经不作数（它不会因此拒绝或延迟拉取）；重新预览一次即可看到同样的清单。[收集降噪](./resolve-and-advanced.md#收集降噪)规则的变化**不会**触发这条提示：普通拉取本来就不读它。

## 拉取进度与取消

真正执行拉取时（无论从哪个入口），编辑器**直接开始下载**，不做预先统计——对巨型仓库来说，统计这次会动到多少个文件本身就要跑上近一分钟，而这段时间一个字节都还没开始传。拉取过程中有三处呼应的进度感：

- **通知区进度条**：显示已处理数量与已用时的**不确定进度条**（如 `421 个文件 · 1m 23s`），随 p4 逐个文件推进。
- **状态栏进度条目**：拉取进行时，客户端名条目**右侧**会出现一条进度条目，显示 `Syncing 421 · 042MB/s · 1m 23s`（操作名 + 已处理数 + 吞吐速率 + 已用时），悬停可见**这次拉取的目标**（`目标：changelist 4521` / `目标：最新版本` / `目标：所选文件`，其余形态如 `#4`、`@2026/08/01` 原样显示）、当前正在拉取的文件、累计读取 / 写入 / 其他字节，以及由 p4delta 执行时的**阶段**。客户端名条目本身不随拉取变化——点它**始终**是打开 [Perforce 图谱](./perforce-graph.md)。
- **拉取阶段（仅 p4delta 引擎）**：由 p4delta 执行的拉取会在已处理数与速率之间多显示一个**引擎自己的阶段词**，形如 `Syncing 0 · scan · 042MB/s · 12s`；悬停可见 `阶段 2/7：scan` 这样的序号（序号与总段数来自引擎自己的阶段表，各类拉取的段数不同）。强制拉取的大半时间花在 **`scan`**（查询与工作区遍历）——这一段既没有文件记录、也没有可看的传输，此前条目上只有停着的 `0`，阶段词就是此时唯一在变的东西。强制拉取的阶段表是 `start` / `scan` / `analyze` / `untracked` / `digest` / `apply` / `done`，其中 **`untracked`** 只在「强制拉取 + 删除未跟踪文件」时出现（忽略规则、client view 与 depot 的三重核对都在这段里），同一段可以连续报几条消息、序号不重复增加。阶段词一律是引擎的原词，不翻译：它报的是引擎实际处在哪一段，换个说法就不再是引擎说的了。
- **状态栏的吞吐速率**：`042MB/s` 是 **p4 进程自己（含并行拉取 fork 出的子进程）的操作系统读取 + 写入计数器之和**；这两个计数器在 Windows 上只统计进程**读写文件与管道**的那部分——网卡收发的字节**不算**在里面，目录枚举与元数据读取也不算，所以这个数字**既不是下载量、也不是落盘量**，它表示的是**进程有多忙**。拉取过程中它从第一次真正落笔就在动（写临时文件、再写进工作区），不会出现「磁盘最忙的时候状态栏反而显示 0」。
- **扫描段回落第三个计数器**：Windows 上「枚举目录、读元数据」这类工作落在一个单独的**其他（other）**计数器里——正是强制拉取开头扫描段在做的事（读/写两边可以长时间一动不动）。所以速率在**读 + 写都为 0 时会回落到第三个计数器**：只有三个都不动，条目才显示 `000KB/s`。悬停时读取 / 写入 / 其他三个累计值分列显示；Linux 上不单列这个计数器（它的读取计数本来就含这些），所以「其他」恒为 0，不是「没在扫描」。数字固定为三位 + 单位（`000KB/s` / `042MB/s` / `999MB/s`），所以数值变化时条目宽度不会跳动，旁边的状态栏条目也不会被推来推去。
- **磁盘计数（没有速率时的回落形态）**：机器上取不到进程计数时（macOS，或 PowerShell / WMI 不可用），条目改为显示 `磁盘 +N`——文件监视器观察到的磁盘写入次数。它是**近似值**（监视事件分批上报、可能被截断，且与 p4 自身的计数不同源），而且只有在**文件已经开始落盘之后**才会动，所以拉取刚开始的服务端比对阶段它同样停在 0。
- **取消**：通知进度条与状态栏进度条目都可取消，**两者都会先弹确认**——点一下不再等于立刻放弃整个拉取；不可取消的操作上，进度条目不响应点击。确认后立即中止：已经落地的文件保留、未完成的保持原状，随后照常刷新；注意取消会**一并中止同一工作区里其它正在进行的 p4 操作**（例如后台的收集改动扫描）。

> **大型拉取不会被中途强杀**：拉取属内容传输，耗时随下载字节数线性增长（整仓拉取合法跑几十分钟），因此不受 `perforce.commandTimeout`（默认 600 秒）约束——它约束的是「永久挂死」的元数据命令，不约束「慢但正常」的下载。拉取过程中随时可点取消中止。
>
> **并行拉取**：`perforce.syncParallelThreads`（默认 `4`，`0` = 串行）给 `p4 sync` 传 `--parallel=threads=N`，对大量中小文件的拉取提速最明显。需服务器允许并行传输（管理员开 `net.parallel.max`），不支持时 p4 自动回落串行、无需手动处理。**该设置只对由 p4 执行的拉取生效**（按修订号 / 按日期拉取，以及 p4delta 不可用时的普通拉取与强制拉取）；由 p4delta 执行的拉取自己调度下载，这个值不起作用——此时 Perforce 输出通道会记一行说明。

> **拉取跑完就查不到了？** 每一次拉取（含失败、取消、已是最新）都会留下一条记录——耗时、文件数、引擎、入口、覆盖路径与进程读写字节，命令面板 **Perforce: 查看同步历史** 打开，见[拉取历史记录](./sync-history.md)。

## 拉取完成的通知

拉取结束时，如果编辑器窗口**不在前台**，编辑器会弹一条**系统通知**（操作系统的通知中心 / 桌面角落），告诉你这次拉取的结果——切去别的窗口干活时不必回来盯着进度条。

- **会通知**：更新了文件、本来就是最新、失败、以及 p4 没给出可识别结果这四种。
- **不通知**：你自己取消的拉取（取消前必然刚确认过一次），以及被[工作区范围](./resolve-and-advanced.md#关于工作区范围)拒绝、根本没跑的拉取。
- 通知正文与编辑器内的结果提示是**同一句话**：文件数、被跳过的拒绝行、失败原因都在里面。
- **点击通知**把编辑器窗口带到前台，接着处理它提到的事——例如「有文件被跳过」的按钮框已经在等你回答。
- 窗口在前台时**不弹**：结果由编辑器内的提示呈现，不会重复打扰。系统层面关闭本应用的通知同样有效。
- 用 `perforce.syncNotifications.enabled`（默认开）可以整体关掉。

## 拉取的作用域

「拉取最新版本」**不会拉整个 depot**。无参执行时（命令面板），作用域是**工作区范围**：

1. 工作区里**没有**范围文件（`.p4delta-scope`）→ 只拉**你打开的文件夹**；
2. 有范围文件 → 只拉「打开的文件夹 ∩ 范围文件里的包含项」，命中的排除项一律排除在外。

也就是说，拉取范围是你**声明的**那部分，而不是 p4 client 映射的全部。游戏项目里 client root 往往映射着比打开的文件夹大得多的树，无差别拉全量既慢、还可能带下你根本不用的分支。编辑、新建或删除范围文件后，作用域会**即时重解析**并生效——细节见[关于工作区范围](./resolve-and-advanced.md#关于工作区范围)。

> 拉取**不跟随**[聚焦目录](../search-navigation/focus-folders.md)：聚焦只收窄后台收集扫描，拉取、收集、清理都按工作区范围执行，不会因为"当前聚焦在看哪个目录"而改变。

> 在 Explorer 里右键拉取时，只针对**右键的那个文件或目录**（目录递归其子目录）——多选时则是**整个选区**，不受上述作用域影响。

> 「他人占用」扫描同样跟随这个作用域，见[性能与配置](#性能与配置)。

## 拉取由谁执行

普通拉取（**拉取最新版本**，以及**拉取指定版本**里的 changelist 档）与**强制拉取**默认交给配套的 **p4delta** 引擎执行（`perforce.p4delta.enabled` 打开、且按 `UNIVERSE_P4DELTA_PATH` → `perforce.p4delta.path` → 编辑器自装副本 → `PATH` → `%LOCALAPPDATA%\Programs\p4delta` 的顺序找得到可执行文件即启用，**不再有版本门槛**；见[关于 p4delta 引擎](./resolve-and-advanced.md#关于-p4delta-引擎编辑器自装副本)）。

- **普通拉取**：δ 做的事与 `p4 sync` **语义完全一致**——先向 p4 预演一次，再把候选逐个按精确修订交回 p4 下载；保护未签出的本地改动、已签出的文件照样只更新版本并挂上待合并，全由 p4 自己判定。
- **强制拉取**：δ 在**本地**算出要修复的集合（按范围文件裁剪，排除项在生成任何 p4 规格**之前**就被剔除），再按精确修订交回 p4 覆盖。这是它与原生的关键差别：`p4 sync -f` 只能拿包含项拼出的规格，**表达不了排除项**，所以带排除的工作区范围在原生的无参强制拉取里会被整体拒绝；交给 δ 则被排除的子树一个字节都不会动。
- **强制拉取并删除未跟踪文件（δ 专属）**：确认框的第二个按钮会给 δ 多传一个删除档。判定「未跟踪」要同时满足：文件在磁盘上、`p4 where` 能把它映射进 client view、且 depot 里没有任何记录（含已打开的文件，opened-for-add 不算未跟踪）。`.p4ignore` 命中的、client view 映射不到的、以及范围外的文件**保留不删**（被忽略的构建产物不会成为牺牲品）；范围里一个 depot 记录都没有时整轮**拒绝执行**，因为分不清「全是未跟踪」与「范围或映射坏了」。这个能力**只存在于 δ**：请求删除档而 p4delta 不可用或版本太旧时，编辑器**不会**悄悄退回原生 `p4 sync -f`（那会静默少删一批文件），而是如实报错；普通强制拉取不受影响。删除完成后的结果提示会单列一句「已删除 N 个未跟踪文件」，不会混进「已更新」。目标修订删掉的**已跟踪**文件同样单列一句「已同步删除 N 个已跟踪文件」——它们确实从磁盘上消失了，但仍不算「更新」；旧记录没有这份拆分，整笔仍按「已更新」显示。

工作区的[范围文件](./resolve-and-advanced.md#关于工作区范围)（`.p4delta-scope`）由编辑器与它**各自读同一份文件**，所以范围解析不依赖 p4delta：引擎不可用时，只是这个操作退回 p4 自己执行（删除未跟踪文件这一档除外，见上）。

**按修订号 / 按日期拉取**（`#4`、`@2026/08/01`）**始终**由 p4 自己执行，强制拉取里的这一档也一样——δ 的契约只认「最新版本」和 changelist 两种目标，没有逐文件修订号的写法。这一档下原生 `-f` 覆盖的正是你明确点名的那些文件，不涉及上面的范围裁剪。

除此之外的 p4 操作（提交、搁置、签出、还原等）也一律由原生引擎执行。

引擎某一轮没有给出结论时（没有 summary、退出码 2、或输出不是 JSON），编辑器会在**同一轮**立刻用原生引擎重做，你只会觉得慢一点、不会看到失败。**两个例外**：① 若这次拉取的范围让原生引擎无法承接（例如范围里 include 内含排除项，原生没有对应写法），编辑器不再回退，而是**如实报出引擎给的原因**——回退只会再报一次范围错误、把真实原因盖住；② **强制拉取**：它没有「预演 → 执行」两段，可能在报错前就已经覆盖了一部分文件，所以任何形态的失败（含退出码 2）都**不会重跑**，只如实报错——重跑会把已经确认要覆盖的东西再做一遍。已经写了一半的普通拉取同样如实报错、不重跑（重跑可能把两边都做过头）。连续 3 次没能给出结论后，**本次会话停用 p4delta**、后续一律走原生引擎（Perforce 输出通道会记一行说明）；改动上述设置即可恢复（失败计数一并清零，编辑器还会重跑一轮扫描把它重新启用）。

无论谁执行，进度、状态栏、取消与结果提示都完全一样。

## 常见拉取错误

从 P4V 迁过来的用户最容易在这里卡住。拉取失败时，编辑器按原因分类给出引导：

| 看到什么（p4 原文） | 意味着什么 | 该怎么做 |
|---|---|---|
| `can't clobber writable file` | 目标文件有**未收集的本地修改**（改了但没签出），p4 拒绝覆盖，且**整次拉取中断** | 错误提示条里有 **收集改动** / **强制拉取** 两个按钮——想保留这些修改就先收集再拉；确定不要时点强制拉取（会再确认一次，永久丢弃这些修改） |
| `can't update modified file` | 同样是「本地改了但没签出」，但你的工作区允许直接改文件（`allwrite`），所以 p4 只**跳过这一个文件**、仍然算成功，同一次拉取里的其它文件照常更新 | 提示条给 **收集改动** / **查看差异** / **强制拉取** 三个按钮，见[有文件被跳过](#有文件被跳过本地改了但没签出) |
| `can't delete modified file` | 服务器在目标版本**删除了**这个文件，但本地副本还有未收集的改动，p4 只**跳过这次删除**、同一次拉取照常进行 | 同上一行（**收集改动** / **查看差异**）：提示条仍会出现，但**强制拉取**列表里不含这类文件——那行带的是你本地已有的修订号，按它拉取会把文件按旧版本复活；被跳过的文件全是这一类时连**强制拉取**按钮也不出现 |
| `can't overwrite existing file` | 本地已有一个 **Perforce 没跟踪的同名文件**占了目标路径（不是你的改动，多为引擎残留的二进制资产），p4 只**跳过这一个文件**、同一次拉取照常进行 | 提示条只给 **强制拉取** 一个按钮（弹出多选列表勾选要覆盖的占位文件），见[有文件被跳过：本地已存在未被跟踪的同名文件](#有文件被跳过本地已存在未被跟踪的同名文件) |
| `must resolve` | 文件存在**未解决的冲突**，必须先合并才能拉 | 先[解决冲突](./resolve-and-advanced.md#冲突解决resolve)，再重新拉取 |
| `file(s) up-to-date` | **不是错误**：已经是最新版本（p4 习惯把它报到 stderr，编辑器会识别并提示「已是最新版本」） | 什么都不用做 |
| `no such file(s)` | 文件不在 depot 中，或不在当前 client 的视图映射内 | 检查是否用错了[工作区](./overview.md#切换工作区client)，或确认文件确实已提交 |
| 其它 | 未识别的 p4 错误 | 提示条显示 p4 原始输出；在面板标题栏 ⋯ 菜单选 **显示输出**，打开 **Perforce 输出**底栏看完整命令日志 |

> 「已是最新版本」只在 p4 真的这么报时才提示。若一次拉取既没更新任何文件、也没给出可识别的结果，编辑器会如实说「没有返回可识别的结果」并给 **打开 Perforce 输出** 按钮——绝不会把不确定的结果说成已是最新。

## 状态感知

### 资源管理器灰字

资源管理器里，Perforce 文件名后会出现灰色小字提示，由两部分驱动：「他人占用」由[后台扫描](#性能与配置)驱动，「落后」由**可见行按需探测**驱动（文件行滚入视野时后台逐个 fstat 判定，不占交互）：

- **✎**：有人正在改这个文件，悬停显示是谁（`user@client`）。对无法自动合并的二进制游戏资源来说，**「别人正在改」比版本号更重要**——动手改之前先看它。
- **↓**：这个文件本机版本落后于服务器最新版（`#have < #head`），悬停显示服务器已到哪个版本。只对你**看得见**的文件行探测（滚入视野才查），不开全量扫描，所以大工作区也不会有额外开销。拉取（sync）后自动消失。

### 状态栏

> 这些条目只在源代码管理侧栏当前选中 Perforce 仓库时才显示；选中 Git 仓库时它们整体隐藏（Git 的分支条目同理只在选中 Git 时显示），避免混合目录里两套状态互相干扰。

Perforce 在状态栏左侧**常态有两个条目**；p4 长操作进行中会在客户端名条目右侧**临时多出第三条进度条目**：

1. **客户端名**（`client 名 N 个已打开`）：连接状态与已打开计数，**点击恒打开 [Perforce 图谱](./perforce-graph.md)**——拉取等操作进行中也一样，它不会变成取消按钮。名字超过 10 字符时保尾截断、前置省略号（优先切在下划线边界）。拉取结束后，悬停里会**保留一行「上次拉取：…」直到下一次拉取**（仅当前会话有效）——错过了右下角的完成通知，也能从这里查出刚才拉的是哪个 changelist。
2. **进度**（仅在 p4 操作进行时出现，位于客户端名条目右边）：拉取（sync）时显示实时计数、吞吐速率与已用时，形如 `Syncing 421 · 042MB/s · 1m 23s`（由 p4delta 执行时，计数与速率之间还会插入引擎自己的**阶段词**，如 `Syncing 0 · scan · 042MB/s · 12s`），悬停除当前正在拉取的文件外，正文下方还给出**这次拉取的目标**（`目标：changelist 4521` / `目标：最新版本` / `目标：所选文件`，其余形态如 `#4`、`@2026/08/01` 原样显示）；扫描工作区（reconcile）时形如 `Scanning workspace 3/12`，数字是 `已扫描目录数 / 已扫描 + 待扫描`；其余 p4 长操作（submit / revert 等）没有计数，形态是 `Submitting…` 加右侧旋转图标。**可取消的操作点击弹确认**（中止的正是它显示的那个操作），不可取消时该条目不响应点击。
3. **当前文件版本**（`#have / #head`）：活动编辑器里那个文件的**本机修订 / 服务器最新修订**。落后时显示 `#have / ↓#head`，点击只拉取**这一个文件**；新加入 depot 的文件显示「新增」。悬停有完整提示。

> 扫描工作区时，`已扫描 / 已扫描 + 待扫描` 里的分母会在扫描过程中**增长**：扫描按广度优先的目录队列推进，遇到较慢的目录会拆成子目录重新入队，于是 `3/12` 可能变成 `8/25`，最终收敛到 `25/25`——这是队列在展开，不是进度倒退。悬停**进度条目**可看完整明细，无需任何配置：第一行补回完整工作区名，之后依次是已扫描 / 待扫描目录数、当前正在扫的目录（批次切换间隙可能不显示，位于工作区根目录时显示「工作区根目录」）、已发现差异文件数与已耗时（不足一分钟为 `12s`，超过为 `1m 12s`）；扫描可取消时末行提示「点击可确认取消」。

### 被忽略的文件变暗

被 `.p4ignore` 规则排除的文件和文件夹，在资源管理器和编辑器标签页上会**变暗（灰色）**显示——和 Git 仓库里被 `.gitignore` 忽略的文件是同一套观感，见[资源管理器与文件操作](../editing/explorer-and-files.md#资源管理器在哪)。

几点值得知道：

- **只有本地文件会变暗**。已经在 depot 里的受控文件即使碰巧命中了忽略规则，也**不会**变暗——它已经被 Perforce 管着了，把它标成「忽略」会误导。
- 编辑 `.p4ignore` 后无需重启：保存即重新判定。但如果你用 `p4 set P4IGNORE=<自定义文件名>` 改过忽略文件的名字，编辑那个自定义文件不会自动触发重判，重开工作区或重载窗口后生效。
- 有本地改动、或带上面那些灰字提示的文件，仍按各自的状态颜色显示，不会被变暗盖掉。
- 一个文件同时归 Perforce 和 Git 管时（比如 p4 工作区里嵌了个 Git 仓库），用谁的忽略规则判定，取决于**源代码管理面板里当前选中的仓库**——切换选中项，变暗结果随之切换。

**「会话更改」视图里的忽略兜底是另一条更宽的判据。** 上面这套走的是 Perforce 扩展：忽略文件名由 `p4 set P4IGNORE` 决定，受控文件会被 fstat 剔除，两者都是「扩展在线」才有的信息。会话更改视图过滤推测条目时，除了问扩展，**编辑器还会自己读规则文件**，因为它必须能回答扩展答不出的三种情况——没装、没激活、以及**离线**（离线时扩展仍在，但一律回答「没有忽略」）。这条兜底路径的能力边界与上面的变暗判定不同：

- 认默认的两个文件名 `.p4ignore` / `p4ignore.txt`，加上环境变量与链上 `.p4config` 里的 `P4IGNORE=`；**读不到** `p4 set` 写进注册表 / `~/.p4enviro` 的自定义名。
- **不做 depot 剔除**：命中规则但已经受控的文件会被当忽略丢掉。只影响「推测」条目，Agent 明确上报的编辑不受影响。拿 `p4 ignores -i -v <路径>` 可以裁决谁对。
- 搜索从文件所在目录逐级向上，**工作区是 client root 的子目录时，根目录的规则文件同样生效**。用 `scm.ignoreFiles.searchCeiling` 可以把它限制在打开的文件夹内。

## 性能与配置

外部工具持续生成、解压或同步大量文件时，编辑器会合并文件事件，并等待上一轮后台改动查询完成后才处理下一轮。连续事件流在 10 秒预算窗口内超过 2,000 个路径次时，暂停这条后台增量查询，避免持续启动 p4 / p4delta；文件事件静默至少 5 秒后，后续变化恢复正常预算。期间不会把未查询的文件当作“没有改动”，但 **Changes 列表与文件夹染色可能暂不完整**，未查询部分留待下次工作区扫描；可见文件的按需徽标查询与手动收集操作不受这个预算限制。

「他人占用」扫描是**后台低频**的：默认每 5 分钟一次，以后台优先级运行、绝不阻塞你的点击。

「他人占用」扫描读的是服务器的打开表——成本随团队的签出活动增长、与工作区大小无关，默认 5 分钟一次。

| 配置项 | 作用 | 默认 |
|---|---|---|
| `perforce.openedByOthers.autoCheck` | 后台「他人占用」扫描 + 灰字。在非常繁忙的共享服务器上可关闭 | 开 |
| `perforce.openedByOthers.intervalSec` | 两次「他人占用」扫描之间的最小间隔秒数（最小 30） | 300 |
| `perforce.syncNotifications.enabled` | 拉取结束时若窗口不在前台，弹[系统通知](#拉取完成的通知) | 开 |

> 关闭自动检查时，已有的灰字会**立即清空**，而不是留下过期的提示。
