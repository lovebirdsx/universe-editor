# 拉取历史记录（同步历史）

每一次拉取（get / sync）都会留下一条记录：拉了多久、动了多少文件、走的是哪个引擎、从哪个入口发起、覆盖了哪些路径、这次 p4 进程读写了多少字节，以及这次拉取**起了多少个 p4 命令进程**。跑完就散的进度提示在这里留了底。承接[拉取版本与状态感知](./sync-and-status.md)。

## 打开方式

两种方式，打开的是同一个标签页：

- 命令面板搜 **Perforce: 查看同步历史**；
- [Perforce 图谱 / 文件历史](./perforce-graph.md)工具栏里，刷新按钮右侧的 🕘 图标。

页面左侧是记录列表（最新在上），右侧是选中那一条的详情。列表的宽度跟着内容走，中间的**分隔线可以左右拖动**——想把更多宽度分给列表或详情都行，拖过的宽度会被记住，下次打开还是它。

打开后键盘焦点会直接落在左侧记录列表上，用 ↑/↓ 就能切换记录，不用先点一下列表。

- 顶部 **N 次同步** 是记录总数，**刷新** 重新读取一次，**导出 CSV…** 把**全部**记录（最多 200 条）写成一个文件：先弹保存框选位置，再写出带 BOM 的 UTF-8 CSV，Excel 直接打开不乱码；列名是字段原名（`outcome`、`durationMs`、`counts.applied`…），供表格工具或脚本消费——**量不到的项留空，不写 0**。p4 调用次数拆成四列（`p4Calls.total` / `.native` / `.p4delta` / `.complete`）：总数照写，**是否完整单独一列标记**，所以「下界」不会被读成确数。调用分类与 δ 运行引用另有三列（`p4Calls.p4deltaByCommand` 写成 `sync=740; ignores=332`、`p4Calls.p4deltaByCommandComplete` 说这份分类是否完整，`deltaRunId`）——没有这些项时同样留空。是否强制、是否带删除未跟踪文件各占一列（`force` / `deleteUntracked`），删掉的数量在 `counts.untrackedDeleted`；记录写在这项能力上线之前时，后两列留空，而不是 `false` / `0`。
- 新拉取落档后页面**会自动更新**：新那条自己出现在列表顶部，当前的选中项和滚动位置都不动（除非你选中的那条正好被 200 条上限挤出去，那会回落到最新一条）。**只有本机其它编辑器窗口发起的拉取不会自动刷新**（记录文件是共享的，但那种写入不会通知这个窗口）——那些点一下 **刷新** 即可。自动更新没有开关，也不需要配置。
- 列表默认加载最近 50 条，底部 **加载更多** 继续往前翻。

> 这个页面是**纯读取**：数据来自 Perforce 扩展写在本地的一份记录文件，**不调用 p4**、不联网、不上传任何内容。

## 每条记录里有什么

列表每行给出：**相对时间 · 结果 · 目标 · 文件数 · 耗时**。点一行，右侧详情分五组：

### 概览

**结果**共六种：

| 结果         | 含义                                                                                                                                                       |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **已更新**   | 拉取成功，有文件被更新（可能同时还有被跳过的文件，见 **文件** 一行）                                                                                       |
| **已是最新** | p4 说这些文件已经是最新版本，什么都没传                                                                                                                    |
| **失败**     | p4 报错中断（如 `can't clobber writable file`）。补救按钮在当时的错误提示条里，这里只留一条记录                                                            |
| **已取消**   | 你在通知进度条或状态栏进度条目上确认取消了这次拉取                                                                                                         |
| **未执行**   | 这次拉取一行 p4 都没有跑。两种情形：被范围门挡住、你选择了不执行；或者编辑器在执行前就判定这次范围没有可执行的写法（详情里的 **错误** 一行会给出具体原因） |
| **无法识别** | p4 退出码为 0，却既没更新任何文件、也没说「已是最新」。编辑器不猜，如实记为无法识别                                                                        |

**开始时间**是这次拉取的启动时刻，**耗时**只算拉取本身——你盯着错误提示条读多久都不计进去，编辑器在拉取过程中自己弹的提示（比如「预览之后范围变了」）若停在那里不点，也一并排除在外。**未执行**的记录耗时恒为 `0ms`：它没跑，就没有可计的时间。失败与无法识别还会带一句提示，让你去 **Perforce 输出** 通道看 p4 的原始输出。

### 传输

- **文件**：七类计数，只列真正发生过的——已更新 N 个 / N 个有未收集的本地修改 / N 个被同名磁盘文件挡住 / N 个已打开编辑 / N 个需要合并 / N 个整批转交 p4 / **N 个未跟踪文件已删除**。最后一项只在选了「强制拉取 + 删除未跟踪文件」且真的删了东西时出现——这些文件不是「同步下来的」，所以单列一句，也不计入「已更新」；只有它的一轮拉取仍算**已更新**，不会被当成什么都没发生。一次都没发生、且这次拉取确实正常结束（已是最新）时显示「无需传输」；**失败或取消的拉取**不会显示「无需传输」，而是「p4 未报告」——p4 没来得及报出计数，和「确实没有东西要传」不是一回事。
- **读取 / 写入**：见下节。
- **落盘**：文件监视器观察到的磁盘写入事件数，一律带 `≥`——它是**下界**（监视事件会分批上报、可能被截断，也遵循 `files.watcherExclude` 等排除设置），不是 p4 写盘的确切次数。

### 执行方式

- **引擎**：`p4delta（δ）` / `p4` / `p4（δ 已试过）`（这一档是 δ 没能给出结论、同一轮退回原生 p4 重做的拉取）。见[拉取由谁执行](./sync-and-status.md#拉取由谁执行)。
- **目标修订**：这次拉的是哪里——最新修订（`#head`）/ 变更列表 4521（`@4521`）/ 所选文件（逐文件拉取无统一目标），`#4`、`@2026/08/01` 这类形态原样显示。
- **强制**：是否 `-f` 强制拉取（会覆盖本地文件的那一档）。
- **删除未跟踪文件**：这次是否选了「强制拉取 + 删除未跟踪文件」——在覆盖之外还从磁盘删掉了范围内 Perforce 从未跟踪的本地文件（语义与保护范围见[拉取由谁执行](./sync-and-status.md#拉取由谁执行)）。删掉的数量记在 **文件** 一行。这个字段只在本能力上线后的记录里存在，旧记录整行不显示——「当时还没有这个能力」不等于「没有删」。
- **并行线程**：这次 p4 用的 `--parallel` 线程数（`串行（0）` 表示关闭）；由 δ 执行的拉取显示 **δ 不使用**——它自己调度下载，这个设置对它不起作用。
- **p4 调用次数**：这次拉取**起了多少个 p4 命令进程**（原生几个 · δ 几个），用来一眼看出「这次拉得贵不贵」。列表行里也给一个总数。注意它数的是**本机启动的 p4 进程数**，不是服务器日志行数——并行传输、p4 内部再发的请求从外面数不出来。

  三种形态：

  | 显示                            | 含义                                                                                                                                                                 |
  | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
  | `7 次 p4 命令（原生 1 · δ 6）`  | 已完整采集，两个来源的分开列出                                                                                                                                       |
  | `≥4 次 p4 命令（… 未完整采集）` | **下界**：δ 起的进程数没被完整上报——那次 δ 版本还不上报调用数（老引擎），或它起了几个进程后没给出最终结论（中途被杀 / 输出异常）。已经发生的调用照数，但总数只会更多 |
  | `未采集（此记录早于该字段）`    | 这条记录写在这项统计上线之前，压根没有这组字段——**不是 0**                                                                                                           |

  一次拉取若 δ 没起、全程原生 p4，就是 `1 次 p4 命令（原生 1 · δ 0）`；δ 从未启动的情况不会把确数写成「未知」。「未完整采集」且总数为 0 时只显示「未完整采集」，**不会**显示成「0 次」。
- **花在哪**：δ 那部分调用按**命令类别**拆开，次数多的在前，例如 `sync 740 · ignores 332 · fstat 3`——回答「这么多次调用到底花在哪」，也正是「下次该优化什么」的证据。类别名就是 p4 的命令名（`sync`、`ignores`、`fstat`…），**不翻译**：它们要和 p4delta 日志、和脚本对得上。这份拆分**是否完整单独判定**：总数是确数不代表拆分也是确数（老引擎只报总数），所以只要拆分不是一份通过验证的完整账，就会注明是下界；引擎不报告分类、或这条记录写在分类上线之前时显示 **未采集（该引擎不报告按命令的分类）**，**不是** 0。原生那一半（编辑器自己起的那一条命令）没有分类可言，只有 δ 这一半有。
- **打开 p4delta 日志**：这次拉取由 δ 执行时会出现一个按钮，打开 δ 引擎自己的**运行日志**——它一步步做了什么、每个阶段收了多少文件、最后是什么结论。日志在**执行这次拉取的那台机器**上（远程开发时不在你本地），以只读**快照**方式在一个新标签页里打开；运行还没结束时打开的是「截至此刻」的样子。日志按运行独立保存、有大小与保留上限（自动淘汰），被清掉或从未落盘时会明确提示，不会打开一个空文件。纯原生 p4 的拉取**没有**这个按钮——它没有 δ 日志，编辑器也不会拿别人的日志来顶替。

  另有两条命令面板命令方便排障：**显示 P4delta 输出**（实时诊断频道，收集改动、清理文件、后台扫描这类不走历史记录的 δ 操作也在这里）与 **打开最近一次 p4delta 日志**（取时间上最近的那一次——包括**此刻仍在跑**的那一次，打开的就是它「截至此刻」的快照）。

### 范围

### 触发入口

这次拉取是从哪儿发起的：**资源管理器**（右键或 Explorer 多选）/ **状态栏修订标记** / **Perforce Graph** / **时间线** / **命令面板** / **自动重试**（失败后由编辑器自己发起的强制重试——它与你先点的那次拉取各记一条，正好能看出补救发生过）。

## 读取 / 写入口径

**读取 / 写入** 是 p4 进程自己（含并行拉取 fork 出的子进程）的操作系统读写计数器，与状态栏那个吞吐速率[同一来源](./sync-and-status.md#拉取进度与取消)：

- 它表示**进程有多忙，不是网络/磁盘的分开计量**。网络接收、中转用的临时文件都算在里面，同一个字节还可能既算读取又算写入，所以数字**高于实际传输的量**。
- 采样按秒进行，**最后不足一秒的部分可能漏计**；同一次拉取里若叠了别的 p4 写操作，这里也会一起算进去。
- 机器上取不到进程计数时（macOS，或 PowerShell / WMI 不可用），这里显示 **不可用（此平台没有采样器）** ——**不是** `0B`。「这台机器量不到」和「这次一个字节都没动」是两件事，不会互相冒充。

## 什么时候会多一条记录

**每个入口的每一次拉取各记一条**，包括：

- 同一批文件在 Explorer 里多选后拉一次 → **一条**（不是每个文件一条）；
- **失败**、**取消**、**已是最新**、被范围门**拒绝**各记一条——这些恰恰是回头查「昨天那次到底怎么回事」时最想看的；
- 拉取失败后点 **强制拉取** 补救 → **两条**：先失败的那次记为「失败 / 资源管理器」，重试记为「强制 / 自动重试」。图谱行右键的 **获取此修订** 记为「Perforce Graph」，状态栏修订标记记为「状态栏修订标记」。

**不会**产生记录的：预览（`p4 sync -n`）这类只读预演，以及收集改动 / 清理文件等其它 p4 操作——这里只记拉取。

## 保留范围与共享

- 记录保存在 Perforce 扩展的全局存储目录里（`syncHistory.json`），**保留最近 200 次拉取**，更早的自动淘汰。翻到某条详情时它若刚好被淘汰，会提示「这条记录已不在历史中」。
- 同一台机器上的**多个编辑器窗口共享同一份**：每个窗口打开页面时读到的都是最新的。**自动更新不跨窗口**——别的窗口拉完，这个窗口里的页面要手动 **刷新**。
- 记录**只在本机**：删掉这个文件即清空历史（扩展下次拉取会重建它）；它不参与任何同步或上报。

## 与图谱「已同步标记」的区别

两者都在回答「我拉到哪了」，但记的不是一回事：

|          | 拉取历史（本页）                            | 图谱的已同步标记                               |
| -------- | ------------------------------------------- | ---------------------------------------------- |
| 记什么   | **每一次拉取**的事件流，永不去重            | 每个范围的**最新同步位置**，会被后来的拉取覆盖 |
| 覆盖范围 | 成功、失败、取消、被拒绝全都记              | 只记能确定落点的成功拉取                       |
| 用来回答 | 「昨天那次为什么这么慢 / 为什么这么多文件」 | 「这个范围现在停在哪个 changelist」            |

所以一次失败的拉取在这里看得到、在图谱里看不到，这是设计如此。图谱侧的细节见[提交历史图](./perforce-graph.md)。
