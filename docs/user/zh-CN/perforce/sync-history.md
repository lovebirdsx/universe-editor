# 拉取历史记录（同步历史）

每一次拉取（get / sync）都会留下一条记录：拉了多久、动了多少文件、走的是哪个引擎、从哪个入口发起、覆盖了哪些路径，以及这次 p4 进程读写了多少字节。跑完就散的进度提示在这里留了底。承接[拉取版本与状态感知](./sync-and-status.md)。

## 打开方式

两种方式，打开的是同一个标签页：

- 命令面板搜 **Perforce: 查看同步历史**；
- [Perforce 图谱 / 文件历史](./perforce-graph.md)工具栏里，刷新按钮右侧的 🕘 图标。

页面左侧是记录列表（最新在上），右侧是选中那一条的详情。列表的宽度跟着内容走，中间的**分隔线可以左右拖动**——想把更多宽度分给列表或详情都行，拖过的宽度会被记住，下次打开还是它。

- 顶部 **N 次同步** 是记录总数，**刷新** 重新读取一次，**导出 CSV…** 把**全部**记录（最多 200 条）写成一个文件：先弹保存框选位置，再写出带 BOM 的 UTF-8 CSV，Excel 直接打开不乱码；列名是字段原名（`outcome`、`durationMs`、`counts.applied`…），供表格工具或脚本消费——**量不到的项留空，不写 0**。
- 页面**不会自动跟随新拉取更新**：拉完之后点一下 **刷新**（或关掉再打开）就会看到新的那条。
- 列表默认加载最近 50 条，底部 **加载更多** 继续往前翻。

> 这个页面是**纯读取**：数据来自 Perforce 扩展写在本地的一份记录文件，**不调用 p4**、不联网、不上传任何内容。

## 每条记录里有什么

列表每行给出：**相对时间 · 结果 · 目标 · 文件数 · 耗时**。点一行，右侧详情分五组：

### 概览

**结果**共六种：

| 结果 | 含义 |
|---|---|
| **已更新** | 拉取成功，有文件被更新（可能同时还有被跳过的文件，见 **文件** 一行） |
| **已是最新** | p4 说这些文件已经是最新版本，什么都没传 |
| **失败** | p4 报错中断（如 `can't clobber writable file`）。补救按钮在当时的错误提示条里，这里只留一条记录 |
| **已取消** | 你在进度条或状态栏上确认取消了这次拉取 |
| **未执行** | 这次拉取一行 p4 都没有跑。两种情形：被范围门挡住、你选择了不执行；或者编辑器在执行前就判定这次范围没有可执行的写法（详情里的 **错误** 一行会给出具体原因） |
| **无法识别** | p4 退出码为 0，却既没更新任何文件、也没说「已是最新」。编辑器不猜，如实记为无法识别 |

**开始时间**是这次拉取的启动时刻，**耗时**只算拉取本身——你盯着错误提示条读多久都不计进去，编辑器在拉取过程中自己弹的提示（比如「预览之后范围变了」）若停在那里不点，也一并排除在外。**未执行**的记录耗时恒为 `0ms`：它没跑，就没有可计的时间。失败与无法识别还会带一句提示，让你去 **Perforce 输出** 通道看 p4 的原始输出。

### 传输

- **文件**：六类计数，只列真正发生过的——已更新 N 个 / N 个有未收集的本地修改 / N 个被同名磁盘文件挡住 / N 个已打开编辑 / N 个需要合并 / N 个整批转交 p4。一次都没发生、且这次拉取确实正常结束（已是最新）时显示「无需传输」；**失败或取消的拉取**不会显示「无需传输」，而是「p4 未报告」——p4 没来得及报出计数，和「确实没有东西要传」不是一回事。
- **读取 / 写入**：见下节。
- **落盘**：文件监视器观察到的磁盘写入事件数，一律带 `≥`——它是**下界**（监视事件会分批上报、可能被截断，也遵循 `files.watcherExclude` 等排除设置），不是 p4 写盘的确切次数。

### 执行方式

- **引擎**：`p4delta（δ）` / `p4` / `p4（δ 已试过）`（这一档是 δ 没能给出结论、同一轮退回原生 p4 重做的拉取）。见[拉取由谁执行](./sync-and-status.md#拉取由谁执行)。
- **目标修订**：这次拉的是哪里——最新修订（`#head`）/ 变更列表 4521（`@4521`）/ 所选文件（逐文件拉取无统一目标），`#4`、`@2026/08/01` 这类形态原样显示。
- **强制**：是否 `-f` 强制拉取（会覆盖本地文件的那一档）。
- **并行线程**：这次 p4 用的 `--parallel` 线程数（`串行（0）` 表示关闭）；由 δ 执行的拉取显示 **δ 不使用**——它自己调度下载，这个设置对它不起作用。

### 范围

**工作区** 是这条记录所属的 client root，下面列出这次拉取覆盖的路径（宿主路径，不是 p4 的 filespec）；列表行里最多列 3 条，详情里列全、超出部分显示「…另有 N 项」。若这次拉取因为工作区范围而收窄过，会额外说明一句（见[拉取的作用域](./sync-and-status.md#拉取的作用域)）。

### 触发入口

这次拉取是从哪儿发起的：**资源管理器**（右键或 Explorer 多选）/ **状态栏修订标记** / **Perforce Graph** / **时间线** / **命令面板** / **自动重试**（失败后由编辑器自己发起的强制重试——它与你先点的那次拉取各记一条，正好能看出补救发生过）。

## 读取 / 写入口径

**读取 / 写入** 是 p4 进程自己（含并行拉取 fork 出的子进程）的操作系统读写计数器，与状态栏那个吞吐速率[同一来源](./sync-and-status.md#拉取进度与取消)：

- 它表示**进程有多忙，不是网络/磁盘的分开计量**。网络接收、中转用的临时文件都算在里面，同一个字节还可能既算读取又算写入，所以数字**高于实际传输的量**。
- 采样按秒进行，**最后不足一秒的部分可能漏计**；同一次拉取里若叠了别的 p4 写操作，这里也会一起算进去。
- 机器上取不到进程计数时（macOS，或 PowerShell / WMI 不可用），这里显示 **不可用（此平台没有采样器）** ——**不是** `0B`。「这台机器量不到」和「这次一个字节都没动」是两件事，不会互相冒充。

## 什么时候会多一条记录

**每个入口的每一次拉取各记一条**，包括：

- 同一批文件在 Explorer 里多选后拉一次 → **一条**（不是每个文件一条）；
- **失败**、**取消**、**已是最新**、被范围门**拒绝**各记一条——这些恰恰是回头查「昨天那次到底怎么回事」时最想看的；
- 拉取失败后点 **强制拉取** 补救 → **两条**：先失败的那次记为「失败 / 资源管理器」，重试记为「强制 / 自动重试」。图谱行右键的 **获取此修订** 记为「Perforce Graph」，状态栏修订标记记为「状态栏修订标记」。

**不会**产生记录的：预览（`p4 sync -n`）这类只读预演，以及收集改动 / 清理文件等其它 p4 操作——这里只记拉取。

## 保留范围与共享

- 记录保存在 Perforce 扩展的全局存储目录里（`syncHistory.json`），**保留最近 200 次拉取**，更早的自动淘汰。翻到某条详情时它若刚好被淘汰，会提示「这条记录已不在历史中」。
- 同一台机器上的**多个编辑器窗口共享同一份**：每个窗口打开页面时读到的都是最新的。
- 记录**只在本机**：删掉这个文件即清空历史（扩展下次拉取会重建它）；它不参与任何同步或上报。

## 与图谱「已同步标记」的区别

两者都在回答「我拉到哪了」，但记的不是一回事：

| | 拉取历史（本页） | 图谱的已同步标记 |
|---|---|---|
| 记什么 | **每一次拉取**的事件流，永不去重 | 每个范围的**最新同步位置**，会被后来的拉取覆盖 |
| 覆盖范围 | 成功、失败、取消、被拒绝全都记 | 只记能确定落点的成功拉取 |
| 用来回答 | 「昨天那次为什么这么慢 / 为什么这么多文件」 | 「这个范围现在停在哪个 changelist」 |

所以一次失败的拉取在这里看得到、在图谱里看不到，这是设计如此。图谱侧的细节见[提交历史图](./perforce-graph.md)。
