# Bug 录制

有些问题只在**你的机器上**出现：同样的操作，维护者照着描述做一遍却什么事都没有。这类问题最难解决的往往不是修，而是让对方看到它。

Bug 录制就是为此设计的：开始录制 → 把问题复现一遍 → 停止，编辑器会把这段过程打包成一个 zip——你做了哪些操作、改了哪些文件、界面报了什么错、关键时刻的屏幕截图、这次运行的日志，都在里面。

和 [导出诊断包](./troubleshooting.md#日志在哪怎么取) 的区别：诊断包是**事后快照**，告诉维护者「出问题时系统是什么状态」；Bug 录制多了**过程**，告诉维护者「你当时做了什么」。复现步骤说不清、或者说清了对方也复现不出来时，录一段比写一百字都有用。

## 怎么录一次

1. **开始**：命令面板（`Ctrl+Shift+P`）运行**开始 Bug 录制**。状态栏右侧会出现一个红色的计时条目，它一直亮着就说明正在录。
2. **复现问题**：照平时那样操作，把问题弄出来。不用刻意放慢或者只做「相关」的操作——多余的步骤不影响分析。
3. **标记关键时刻**（可选，但很有用）：问题出现的那一瞬间运行**标记 Bug 录制步骤**。它会在时间线上留一个标记并抓一张截图，维护者能直接跳到这一刻，不用从头猜。
4. **停止**：运行**停止 Bug 录制并导出证据包**，或者直接点状态栏那个红色计时条目。
5. **选择保留还是脱敏**：会弹出一个对话框问你要不要脱敏，见 [下一节](#保留还是脱敏)。
6. **发给维护者**：导出完成后文件管理器会自动打开并选中生成的 zip 文件，直接把它作为附件发出即可。

如果录制过程中发现录错了、或者问题没复现出来，停止时选**继续录制**可以回到录制状态接着来；想彻底放弃就先停止导出，再把 zip 删掉。

## 保留还是脱敏

停止时的对话框有三个选择：

- **保存证据包**（推荐）：保留全部信息。
- **脱敏并保存**：把用户名、账号目录、项目路径和密钥 token 替换成占位符再打包。
- **继续录制**：什么都不做，回到录制状态。

**默认推荐「保存证据包」，因为脱敏抹掉的东西往往正是问题的原因。** 很多 bug 恰恰和特定路径、特定用户名有关——比如路径里带空格或中文、用户名含特殊字符、项目放在某个特殊位置。这些信息被替换成占位符之后，维护者看到的就只是「某个路径」，那条线索就断了。

只有当你确认包里可能含**不能外传**的内容时（客户项目名、内部代号、真实账号），才选脱敏。

**截图无法脱敏。** 截图是屏幕画面，脱敏只能处理文字，处理不了图片。如果录制期间屏幕上出现过不该外传的东西，请自己解压 zip 检查 `screenshots/` 目录，删掉不合适的图片之后再重新压缩发出。

## 包里有什么

zip 里的内容（导出后可以自己解压看，全部是文本或图片，没有加密）：

| 内容                     | 说明                                                 |
| ------------------------ | ---------------------------------------------------- |
| 时间线（`timeline.md`）  | 按时间排序的操作与错误汇总，主要给维护者/AI 阅读     |
| 事件流（`events.jsonl`） | 同一批信息的结构化版本，便于程序分析                 |
| 截图（`screenshots/`）   | 关键时刻的屏幕画面，最多 25 张                       |
| 日志                     | 本次运行的日志尾部                                   |
| 错误记录                 | 本次运行记录到的错误                                 |
| AI 对话记录              | 录制期间用过 Agent 的话，会附带对话内容（最多 5 段） |
| 环境信息                 | 版本、系统信息、已安装扩展——和诊断包里的一样         |
| 脱敏说明                 | 这次导出有没有脱敏、脱敏了哪些内容                   |

zip 存放在编辑器数据目录的 `bug-recordings` 子目录下（Windows 上是 `%APPDATA%\Universe Editor\bug-recordings\`）。导出后文件管理器会自动定位到它，一般不需要手动去找。

## 不会记录什么

Bug 录制只记「你做了什么」这一层，不做屏幕录像，也不逐字记录你敲的内容：

- **不记录按键内容**。文本编辑只记「哪个文件被改了几次」，不记具体改成了什么。
- **不记录普通提示**。只记录警告和错误级别的提示，日常的操作成功提示不入账。
- **不记录录制之外的任何操作**。没点开始录制之前、以及停止之后的操作完全不采集，录制未开启时这个功能零开销。
- **截图只在关键节点抓**，不是持续截屏。触发时机只有五种：录制刚开始、某个命令执行失败、弹出错误提示、你向 AI Agent 发送提问、你手动运行了标记命令。同一 1.5 秒内不会重复抓，最多保留最近 25 张（超出后自动丢弃最旧的）。

## 录制中崩溃了怎么办

**崩溃时的录制不会丢。** 如果编辑器在录制过程中崩溃或被强制结束，已经记录的内容仍然在磁盘上。

下次启动时你会收到一条常驻的警告通知，说明上次有一段录制被中断、以及它记了多少条事件。点通知里的**导出证据包**就能把它补导出来（同样会问你要不要脱敏）；暂时不想处理就点**暂不导出**，通知关掉即可。

崩溃类问题的现场恰恰是最值得反馈的，遇到这个提示建议顺手导出。

> 隐私说明：录制内容完全在本地生成，导出的 zip 也只是保存在你自己的磁盘上——**在你主动把它发出去之前，不会有任何内容离开你的电脑**。但请注意：与诊断包不同，Bug 录制**默认不脱敏**（这是有意的，见 [保留还是脱敏](#保留还是脱敏)），所以发出前如有顾虑请自行解压确认，尤其是无法脱敏的截图。

## 本页涉及的命令

| 命令面板名称              | 命令 id                                 | 快捷键 |
| ------------------------- | --------------------------------------- | ------ |
| 开始 Bug 录制             | `workbench.action.startBugRecording`    | 无     |
| 停止 Bug 录制并导出证据包 | `workbench.action.stopBugRecording`     | 无     |
| 标记 Bug 录制步骤         | `workbench.action.markBugRecordingStep` | 无     |

三个命令都在命令面板的**开发人员**分类下，输入「Bug 录制」即可找到。
