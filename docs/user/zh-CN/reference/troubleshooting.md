## 装不上 / 打不开

按顺序检查：

1. **系统要求**：确认是 Windows 10 或更高版本（64 位）。当前主要支持 Windows。
2. **被 SmartScreen 拦下**：首次运行弹出"Windows 已保护你的电脑"是正常的——当前产物未做代码签名。点**"更多信息"→"仍要运行"**放行。详见 [下载与安装 · 处理 Windows SmartScreen 警告](../getting-started/installation.md#处理-windows-smartscreen-警告)。
3. **杀毒软件拦截**：个别安全软件会对未签名程序更激进，必要时在其信任列表里放行。
4. **绿色版打不开**：如果用的是 `win-unpacked` 免安装目录，确认整个目录完整解压（不要只拷贝单个 exe），再运行里面的可执行文件。

装好后看到**欢迎页**就说明启动成功，详见 [下载与安装 · 首次启动](../getting-started/installation.md#首次启动)。

## Agent 连不上 / 无回复

Agent 发出去没反应、或报错时，按这个顺序查：

1. **是否配了供应商和模型**：这是最常见的原因。没有可用模型时会话发不出有效回复。去 [AI 供应商配置](../customization/ai-providers.md) 添加一个供应商、填好模型。
2. **密钥是否设置正确**：在 AI 设置里打开对应供应商，密钥未设置时会显示「未设置」，点「编辑 API 密钥」填好；卡片顶部的连通性状态点会自动探测，能列出模型就说明密钥可用。
3. **看具体报错**：内联补全等功能会给出明确的错误文案，对照下表判断根因——

   | 界面提示                     | 含义                      | 怎么办                 |
   | ---------------------------- | ------------------------- | ---------------------- |
   | API 密钥被拒绝（请检查密钥） | 密钥无效或填错            | 重新设置正确的密钥     |
   | 额度或余额已用尽             | 供应商账户额度 / 余额不足 | 去供应商侧充值或换分组 |
   | 请求频率受限，请稍后重试     | 触发了供应商限流          | 稍等片刻再试           |
   | 连接提供方时发生网络错误     | 网络不通 / 端点地址不对   | 检查网络与 Base URL    |
   | 所选补全模型缺失             | 选中的模型已不存在        | 重新选择一个模型       |

4. **换个 Agent 试试**：内置有 Claude Code 和 Codex 两个 Agent，可用"选择 Agent 并新建会话…"切换验证。列表里标注"未安装（PATH 中找不到命令）"的 Agent 不可用。
5. **仍不行**：取一份日志便于反馈，见 [日志在哪、怎么取](#日志在哪怎么取)。

> 会话运行**中途**遇到限流、Agent 崩溃或长时间卡住时，编辑器会在输入框上方弹出状态条**自动重试 / 重连**并恢复被打断的那一轮，通常无需你手动干预；细节与手动重试见 [管理会话 · 中断自动恢复](../ai-agent/managing-sessions.md#中断自动恢复)。

相关：[你的第一次 Agent 会话 · 开始前先配好模型](../ai-agent/first-session.md#开始前先配好模型)。

## 内联补全不工作

内联补全（灰色幽灵文本）不出现时：

- **先配模型**：补全需要一个可用模型，没配时手动触发会弹提示引导你去选。见 [内联补全 · 开始前先配好模型](../editing/inline-completion.md#开始前先配好模型)。
- **是否被关掉**：运行"开关内联补全"确认它是开启状态。
- **手动触发**：把光标放进可编辑文本文件，按 `Alt+\` 主动求一条建议。
- **报错含义**：对照上一节的错误提示表。

详见 [内联补全（幽灵文本）](../editing/inline-completion.md)。

## 检查更新与升级

- **标题栏提示**：有更新可用或已下载待安装时，标题栏中间会出现一个带文字的醒目按钮（如"Update"、"Restart to update"），点击即可下载或重启安装；后台检查、下载中也会在此显示状态。
- **手动检查**：命令面板运行**检查更新**，编辑器会告诉你是"已是最新"、"发现新版本"还是"检查失败"。
- **发现新版本**：按提示下载；下载完成后会提示"版本 X 已准备好安装"，此时运行**重启以更新**（或点通知里的"立即重启"）完成安装。安装期间会短暂显示安装进度窗口，无需任何操作，装完自动重新打开编辑器。
- **检查失败**：多半是网络问题，稍后重试；持续失败可去 GitHub Releases 手动下载新版本覆盖安装。
- **自定义更新地址**：内网/自建更新源可运行命令面板的**打开更新配置 (JSON)**，在 `update-config.json` 里填 `updateUrl` 覆盖更新服务器（仅打包版生效）。

## 日志在哪、怎么取

反馈问题时附上日志能大大加快定位。最简单的方式是一键打包：

1. **报告问题（推荐）**：命令面板运行 **报告问题...**，编辑器会自动生成一份诊断摘要（版本、系统信息、已安装扩展、近期错误聚合）并复制到剪贴板，然后询问是否**附带诊断包**（附带时会自动上传为帖子附件），最后在浏览器中打开预填好的上报页面，你只需补充标题和问题描述。默认上报到问题追踪系统（Tracker），也可用设置项 `issueReporter.provider` 切换为 GitHub Issues（不支持附件）；问题追踪系统的服务器地址、板块、分类可在 `issueReporter.tracker.*` 设置项中调整（其中 `serverUrl` / `appUrl` 默认为空，需先填写才能上报）。
2. **导出诊断包**：命令面板运行 **导出诊断包...**，会把诊断摘要、近期错误记录与最近日志尾部打包成一个 zip 并在文件管理器中显示，直接把它发给维护者即可。
3. **手动取日志**：命令面板运行**开发人员：显示日志...**（`Ctrl+Shift+U`）挑日志文件查看；运行**开发人员：打开日志文件夹**在系统文件管理器里打开日志目录自行打包。
4. **Bug 录制**：如果问题**只在你的机器上出现**、或者复现步骤说不清、说清了对方也复现不出来，改用 [Bug 录制](./bug-recording.md)——它会把你复现问题的整个过程（操作步骤、关键截图、日志）打包成一份证据包，比诊断包多了「你当时做了什么」这一层。

把诊断包或相关日志连同"你做了什么、期望什么、实际发生了什么"一起反馈，最有帮助。

> 隐私说明：诊断内容完全在本地生成，未经你主动导出/发送不会离开你的电脑；摘要与错误记录中的用户目录路径、密钥等敏感信息会被自动脱敏。可用设置项 `telemetry.errorCollection.enabled` 关闭本地错误记录。

**界面崩溃 / 异常退出**：若编辑器窗口意外崩溃，会弹出"编辑器窗口已崩溃"对话框，点**重新加载**即可恢复窗口。若整个应用上次未正常退出（崩溃或被外部强制结束），下次启动时会收到一条警告通知，可点**打开崩溃目录**查看崩溃转储文件；反馈问题时建议同时导出诊断包（其中包含崩溃转储清单、最新的崩溃转储文件与错误记录）。若崩溃时正在进行 [Bug 录制](./bug-recording.md)，启动后还会收到一条「录制被中断」的通知，点其中的**导出证据包**可把崩溃现场一并导出。

**反复闪退、一打开就崩**：若应用**连续 2 次及以上**异常退出且上次有待恢复的工作区，下次启动会先弹出"连续异常退出"对话框——崩溃可能正是由恢复的工作区触发（例如包含海量文件的目录）。选择**跳过恢复（打开空窗口）**可以先以空窗口启动进行排查（导出诊断包、查看日志）；之前的目录不会丢，仍可从**文件 → 最近打开**重新进入。选择**正常启动**则照常恢复工作区。连续 **4 次及以上**异常退出时，对话框默认选中**跳过恢复**（直接回车或 Esc 即以空窗口启动），避免恢复引发的崩溃循环。

**界面卡顿 / 交互变慢**：编辑器会常驻监控交互响应，任何变慢的交互（打字、点击、切标签页）都会自动在窗口日志的 `interactionPerf.log` 里留下一行记录（慢在哪、当时主线程在跑什么）。命令面板运行**开发人员：交互性能**可查看本次会话的交互统计与最慢明细；可用设置项 `performance.responsiveness.enabled` 关闭监控、`performance.responsiveness.warnThresholdMs` 调整判定阈值。

**恢复超大 Agent 会话导致内存不足崩溃**：如果某个 Agent 会话历史特别大（例如包含大量工具输出或大图片），恢复它时窗口可能因内存不足（OOM）崩溃。编辑器对此有三道防线：超大图片/长文本/大 diff 在入库时会被截断为占位内容；单次恢复的历史摄入超过 256MB 时会丢弃剩余历史并在会话里提示"会话历史过大，仅加载了部分历史"；若窗口刚因内存不足崩溃过（5 分钟内），重启后**不会**自动恢复该会话，而是显示"上次加载此会话时窗口因内存不足崩溃，已暂停自动恢复"的占位页——确认后点**继续加载**可手动恢复。若某会话反复触发，建议导出诊断包反馈。

## 界面卡顿或资源占用高：用进程管理器定位

界面明显变卡、风扇狂转，或怀疑编辑器占用了过多 CPU / 内存时，可以用内置的**进程管理器**看到底是哪个进程在消耗资源：

1. 命令面板（`Ctrl+Shift+P`）运行 **Developer: Open Process Explorer**（目前只显示英文，用英文关键词搜索），会打开一个「Process Explorer」编辑器页签。
2. 页签里以表格树展示本应用的全部进程——main 主进程、各窗口 renderer、GPU/utility 进程、extension host、AI agent（acp-agent）、集成终端 pty、tsserver、ripgrep 等，进程名称带角色标注；列有 CPU (%)、PID、内存 (MB)，约每秒刷新一次。
3. **CPU 高于 90% 的行会高亮**，一眼就能找到元凶；结合角色标注判断是哪个功能（如某个终端、AI agent 或 TypeScript 服务）导致的。
4. 右键某行可 **Kill Process**（结束该进程，Windows 上等同强制结束，可用于结束卡死的终端 pty 或失控的 agent 子进程）、**Copy**（复制该行）或 **Copy All**（复制整棵进程树文本，便于贴给维护者）。

**导出诊断包...** 导出的诊断 zip 里也会附带一份 `processes.txt`——导出那一刻的进程树快照（含 CPU / 内存），反馈性能问题时一并提供可辅助离线分析。

## Git 没反应

源代码管理侧栏空空的、Git 命令像没生效：

1. **当前目录不是 Git 仓库**：这是最常见的原因。版本控制只对仓库生效。本编辑器**没有内置"初始化仓库"命令**，需用系统 Git 执行 `git init`，或克隆一个已有远程仓库。详见 [版本控制 · 让你的项目变成仓库](../git/overview.md#让你的项目变成仓库)。
2. **[Git 图谱](../git/git-graph.md) 提示不可用**：出现"Git 图谱不可用 - 此文件夹是 git 仓库吗？"同样是因为当前目录不是仓库。
3. **没装系统 Git**：Git 集成依赖你系统里安装的 Git。若从未装过，先安装 Git 再重开项目。
4. **推送 / 拉取失败**：常见提示与处理见 [拉取、推送、储藏与冲突 · 常见错误提示](../git/conflicts.md#常见错误提示)，例如"请先拉取，或使用强制推送"、"请先提交或储藏您的本地更改"。
