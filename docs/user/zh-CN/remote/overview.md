# 远程开发

远程开发让你把「编辑体验留在本地、代码与文件系统放在远端」——像 VSCode 的 Remote-SSH 一样，Universe Editor 通过 SSH 连到一台 Linux 主机，在那台机器上部署一个轻量 server，把文件浏览、搜索、保存等操作路由到远端执行，本地的编辑器则负责界面与交互。在 Windows 上，本机安装的 **WSL 发行版会被自动识别**，无需配置 SSH 即可一键连入。

这一页讲清前置条件、怎么连、连上后有哪些入口与状态反馈，以及出问题时去哪看日志。

## 前置条件

**以 SSH 连接远端主机时：**

- **远端主机**：一台能通过 SSH 登录的 **Linux** 主机。
- **远端环境**：远端主机上已安装 **Node.js ≥ 20** 和 **npm**（编辑器需要它们把 server 部署并跑起来），且 `node` 在**非交互 SSH 会话**下也必须在 PATH 里可用（用 nvm 安装时请确认初始化脚本写进了 `~/.bashrc` / `~/.profile`，见下方排障）。
- **本地 SSH**：本地已配置好 `~/.ssh/config` 或能直接用 `user@host[:port]` 免密登录（SSH 密钥认证）。连接过程会以非交互方式（BatchMode）运行 `ssh`，如果登录需要你手输密码，连接会失败——请先配好密钥。

**连接本机 WSL 时（Windows）：**

- **不需要 sshd、不需要查 IP、不需要配免密**——编辑器会自动枚举本机已安装的 WSL 发行版，直接通过 WSL 通道连入。
- 唯一要求：发行版内已安装 **Node.js ≥ 20**，且在 **bash 登录 shell** 中可见（编辑器以 `bash -l` 方式探测）。用 nvm 安装的 Node 请确认 nvm 的初始化脚本写在 `~/.bashrc` 或 `~/.profile` 里（默认安装即如此），否则可能探测不到。

## 连接流程

1. 打开命令面板（`Ctrl+Shift+P`），运行 **Remote-SSH: Connect to Host…**；或在左侧 **远程资源管理器** 里点击某台主机的连接图标。
2. 在弹出的列表里选择 `~/.ssh/config` 里的主机，或直接输入 `user@host[:port]`。装有 WSL 时，列表底部还会出现 **WSL Targets** 分组，选中即可连入对应发行版。
3. 编辑器通过 SSH 连上远端，自动部署并启动 server（首次连接会慢一些，进度会显示在窗口底部）。
4. 部署完成后，在远端主机的主目录里选择一个文件夹，作为工作区打开。

之后就可以像操作本地文件夹一样浏览、打开、搜索远端文件了。

**连接 WSL**：也可以直接运行 **WSL: Connect to WSL…**——只装了一个发行版时直接连入；装了多个则弹出列表（默认发行版排最前）。或在 **远程资源管理器** 的 **Targets** 视图里展开 **WSL** 分组，点击某个发行版的连接图标。后续的 server 部署与文件夹选择流程与 SSH 相同。

**新建窗口与打开文件夹**：在远端窗口里运行 **New Window**（`Ctrl+Shift+N`）打开的新窗口会保持同一远程连接——在这个新窗口里执行 **Open Folder** 时，文件选择器直接从远端主目录开始浏览，选中的文件夹以远端工作区打开。只有本地窗口新建出的窗口才回到本地文件系统。

## 命令速查

这些命令都归在命令面板的 **Remote-SSH** 分类下（WSL 命令在 **WSL** 分类），当前显示英文原名：

| 命令                 | 作用                                                                                                 |
| -------------------- | ---------------------------------------------------------------------------------------------------- |
| Connect to Host…     | 连接一台主机（或输入 `user@host[:port]`）并打开远端文件夹；列表里也会列出本机 WSL 发行版             |
| WSL: Connect to WSL… | 连接本机 WSL 发行版（单个直连，多个弹出列表）                                                        |
| Open Folder on Host… | 在已连接的主机上另选文件夹打开                                                                       |
| Close Connection     | 关闭到某主机的连接，并关闭该主机对应的窗口；若当前窗口正打开着该主机的工作区，会先弹确认框；关完若不再剩窗口，会自动打开一个本地空白窗口 |
| Retry Connection     | 重试一条失败的连接                                                                                   |
| Stop Remote Server   | 停止远端主机上的 server 并断开连接；所有使用该主机的窗口会一并关闭（确认框会列出受影响的工作区；若有会话正在运行，关闭前还会像本地关窗一样再次确认）；若关完不剩窗口，会自动打开一个本地空白窗口；停止后不再自动重连 |

## 界面标识

远程状态下，编辑器会在多处给你「当前连着谁」的明确标识。

### 状态栏远程指示器

状态栏**最左侧**有一个远程指示器，它同时反映了连接状态（从本地窗口发起连接时，该条目在连接进行中也会出现）：

- **本地窗口**：显示一个无底色的远端图标作为入口。
- **远程工作区**：变成**蓝底**徽章，显示 `WSL: <发行版>`（连 WSL 时）或 `SSH: <主机>`（连 SSH 主机时），带远端图标。
- **连接中**（部署 / 转发 / 握手）：在名称后追加状态后缀，如 `SSH: <主机> (Connecting...)`，图标转圈。首次连接（或 server 版本变化）需要上传并安装远端 server 时，会进一步显示具体步骤和已耗时，如 `SSH: <主机> (Step 2/3: Uploading server bundle · 45s)`，此时底部 **Output 面板**会自动打开并定位到 **Remote Connection** 频道，实时滚动部署日志。
- **重连中**：显示 `SSH: <主机> (Reconnecting...)`，图标同步动画。
- **失败**：变成红底，显示 `SSH: <主机> (Failed)`，前缀带警告符号。

点击指示器会弹出远程菜单：远端状态下包含 **Open Folder on Host…**、**Connect to WSL…**（检测到 WSL 发行版时）、**Close Connection**、**Retry Connection**、**Stop Remote Server**；本地状态下只有 **Connect to Host…** 和 **Connect to WSL…** 两个连接入口。

### 标题栏徽章与路径

- 标题栏**命令中心左侧**会显示一个与状态栏同款的蓝底徽章（如 `WSL: ubuntu-24.04`），点击弹出同样的远程菜单。
- 标题栏的窗口标题在远程状态下显示的是**服务器侧路径**（如 `/home/you/proj`），不再是冗长的 `remote-ssh://` URI。

### 窗口标题

远程状态下，操作系统窗口标题（任务栏、Alt+Tab 切换器里可见）会以 `⇄ ` 前缀开头（如 `⇄ myproj — ● 修复Bug`），一眼就能分辨哪个是远端窗口；本地窗口没有这个前缀。完整的连接目标（`WSL: <发行版>` / `SSH: <主机>`）仍显示在标题栏徽章和状态栏指示器里。同样的 `⇄ ` 前缀也用于 **Open Recent**（Ctrl+R）与 **Switch Window**（文件菜单）列表中：远程工作区/远程窗口的条目名称以 `⇄ ` 开头，本地条目不带前缀。

### 欢迎页最近工作区

欢迎页的 **Recent** 列表里，远端工作区条目会带一个蓝色的远端图标，路径一行显示 `WSL: <发行版> · <服务器路径>` 或 `SSH: <主机> · <服务器路径>`（如 `WSL: ubuntu-24.04 · /home/xiao/proj`），不再显示冗长的完整 URI；悬停条目时提示里仍是完整 URI。本地条目的显示不变。

## 断线自动重连

远端连接意外中断（比如 SSH 掉线）时，编辑器会自动尝试透明重连：

- 掉线超过约 1 秒，弹出「Connection to <主机> lost. Reconnecting...」的进度通知。
- 重连成功：关闭进度通知，并短暂提示「Reconnected to <主机>.」。
- 重连失败：弹出错误通知，提供 **Retry**（重试连接）和 **Close Remote Workspace**（关闭远端工作区）两个按钮；通知会显示具体失败原因（如「Node.js was not found...」）。同一连接的反复失败只会弹一条通知，不会叠加；只有连接真正恢复后再次失败、或你点过 **Retry**，才会重新弹出。**Close Remote Workspace** 会真正关闭该主机对应的窗口（而不只是清空工作区），若关完不剩窗口会自动打开一个本地空白窗口。

短暂的网络抖动（1 秒内即恢复）不会弹通知，避免闪烁。

## 远程资源管理器

左侧活动栏有一个**远程资源管理器**标签页，里面是一个 **Targets** 树视图，分为 **SSH** / **WSL** 两个可折叠分组（点击分组行或行首箭头可折叠/展开）：

- **SSH** 分组：`~/.ssh/config` 里的主机 + 你手动添加的主机（该分组始终显示；没有主机时给出添加提示）。每行有状态圆点（灰=未连、绿=已连、橙=连接中、红=失败）；**点击行即执行当前状态下的主操作**：未连接=连接主机、已连接=在主机上打开文件夹、失败=重试连接。悬停行右侧也会浮出对应图标按钮，已连接时还包括 关闭连接 / 停止 server。视图标题栏右侧的 **+** 可以手动添加 `user@host[:port]`，手动添加的条目旁有「忘记」按钮可删除。右键任意行可打开包含全部动作的菜单。
- **WSL** 分组（检测到 WSL 发行版、或存在 WSL 连接/最近工作区时显示）：本机已安装的 WSL 发行版列表，默认发行版标有 `default`。行为与 SSH 分组一致：状态圆点反映连接状态，点击行即可按状态连入/打开文件夹/重试，也有悬停按钮与右键菜单。
- 有活跃连接或最近工作区、但不在上述列表里的主机，也会合成一行显示，保证连接信息不丢失。
- 每个主机下，它最近打开过的远端工作区会作为缩进子行列出（按最近打开排序），点击在**当前窗口**重新打开；按住 **Ctrl**（macOS 为 **Cmd**）点击则在**新窗口**中打开。右键菜单提供「Open in Current Window」/「Open in New Window」两项等价入口；悬停按钮或右键菜单的「Remove from Recently Opened」可移除。

## 远程终端

在远端工作区里打开集成终端时，终端会自动跑在**远端主机**上，工作目录是远端工作区的根目录（而不是本地目录）。你仍像平时一样打开终端、输入命令——但进程与文件操作都落在远端。用户配置的 `terminal.integrated.cwd` 只在本地工作区生效，远端终端会忽略它并回退到工作区根目录。

## 远程下的 AI 会话

在远端工作区里新建 AI 会话（ACP agent，如 Claude / Codex）时，agent 进程同样跑在**远端主机**上：

- **工作目录**是远端工作区的根目录，agent 读写、搜索、执行命令都落在远端文件系统。
- **agent 程序自动下载到远端**：Claude / Codex 的原生程序体积较大，不随 server 部署。首次在远端工作区启动某个 agent 时，编辑器会把它下载到远端主机的 `~/.universe-editor-server/agent-bin/` 下（下载进度会以通知显示，之后复用无需重新下载）。这要求远端主机能访问 npm registry；本地设置里的 agent 程序来源（系统安装 / 自定义路径）只对本地会话生效，远端固定使用受管下载。
- **凭据天然使用远端**：agent 读取的是远端主机的 `~/.claude` / `~/.codex`（登录状态、配置、skills、memory 等），因此你在远端机器上已登录的凭据会直接生效。
- **本地凭据不会带过去**：编辑器不会把本机的 token、密钥或登录状态通过隧道传给远端——本地和远端的凭据完全隔离，各自独立登录。
- **设置页同样操作远端**：远端工作区里打开 AI Settings 的 Claude Code / Codex 设置页，认证、模型、env 等读写的都是远端主机的配置文件；「打开配置文件」链接打开的是远端文件，网关连通性探测也从远端网络发起。凭据档案库（保存的候选凭据）仍存在本地编辑器，「使用」某档案时才写入远端。登录按钮会在远端终端里运行 CLI 登录流程（Claude 需要远端 PATH 中有 `claude` CLI）。

也就是说：远端工作区里的 AI 会话等于「在远端机器上开了一个 agent 终端」，一切身份与文件都归远端所有；回到本地工作区后，本地会话照常使用本地凭据。

## 远程下的扩展

在远端工作区里，扩展宿主（extension host）也跑在**远端主机**上：

- **内置扩展**（git、TypeScript、markdown 等）会随远端 server 一起部署，在远端正常工作——比如 TypeScript 的语言服务（tsserver）和 git 仓库操作都直接在远端执行。
- **你手动安装的扩展不会同步到远端**。在远端工作区中，这些扩展不会激活，扩展视图里会给它们标一个「Unavailable in Remote」徽标，表示它只在本地可用。

也就是说：远端工作区里能用的扩展 = 内置扩展；本地手动安装的扩展回到本地工作区后照常生效。

## 远程下的本机操作

有几类操作本质上作用于**本地操作系统**，在远端工作区里的行为如下：

- **打开所在文件夹 / 使用默认应用打开 / 打开会话位置**：这些操作打开的是本地文件管理器或本地应用。在 **Windows 上连接 WSL** 时它们照常可用——编辑器会把远端路径翻译成 `\\wsl$\<发行版>\…` 路径交给 Windows 资源管理器。其它远程连接（如 SSH 到别的主机）下没有对应的本地路径：菜单里这些项会隐藏或置灰，通过快捷键、命令面板触发时会提示"该文件位于远程主机，无法在本地文件管理器中打开"。
- **在资源管理器中定位**（编辑器内的文件树定位）不受影响，远端工作区里照常可用。
- **在 VS Code 中打开工作区**：WSL 远端工作区会以 `code --remote` 方式在 VS Code 里打开对应的 WSL 远程窗口；其它远程类型暂不支持，会给出提示。

## 排障

- **提示 `Node.js was not found`**：远端主机上没有可用的 Node.js（或非交互 SSH 会话里 PATH 找不到 node）。在远端装好 Node.js 20+ 后直接重连即可，无需手动清理 `~/.universe-editor-server` 目录。
- **看日志**：本地这一侧的连接与部署日志（检测、上传、安装、启动各步骤及耗时）在 **Output 面板**的 **Remote Connection** 频道，首次安装时会自动打开；远端 server 自身的日志在远端主机的 `~/.universe-editor-server/server.log`。部署、连接、转发失败，先看这两处的具体报错。
- **停止 server**：想彻底停掉远端那台进程，运行 **Remote-SSH: Stop Remote Server**（或在状态栏条目菜单 / 远程资源管理器里点停止）。确认框会列出所有使用该主机的窗口——确认后这些窗口会一并关闭（有会话正在运行时，关闭前还会像本地关窗一样再次确认，取消即整体中止、server 保持运行）；若关完不剩窗口，会自动打开一个本地空白窗口。停止后会抑制自动重连——server 不会被后台立刻拉起；重新打开该主机的远程工作区即可再次连接。
- **开发期自定义启动命令**：开发模式下可用环境变量 `UNIVERSE_REMOTE_SERVER_CMD` 指定启动远端 server 的命令（用于联调自建 server，仅开发环境生效）。

### 以 SSH 方式连接 WSL（旧方式，仍可用）

现在连接本机 WSL 推荐直接用 **WSL: Connect to WSL…**（自动识别，无需下面这些配置）。如果你仍想把 WSL 当作一台普通 SSH 主机来连（例如从另一台机器连过来），注意：

- **别用 `localhost` 连**：若 Windows 自带的 OpenSSH Server 服务也在运行，它会占住 22 端口，`ssh localhost` 连到的是 Windows 而不是 WSL。用 `wsl hostname -I` 查出 WSL 的虚拟网卡 IP（如 `user@172.x.x.x`）来连；该 IP 在 WSL 重启后可能变化。
- **Node 版本要对非交互 SSH 生效**：编辑器通过非交互 SSH 执行远端命令。若你的默认 shell 是 zsh，非交互会话只读 `~/.zshenv`（不读 `.bashrc`/`.zshrc`）——用 nvm 装的 Node 需要把 PATH 导出写进 `~/.zshenv`，否则连接时可能探测到系统旧版 Node 而失败。
- **WSL 会闲置自动关机**：没有活动交互会话时 WSL 可能自动停止，导致连接中断且无法重连（Connection refused）。从 Windows 侧起一个保活进程（如 `wsl -- sleep 7200`）或在 `.wslconfig` 调整 `vmIdleTimeout` 可避免。
